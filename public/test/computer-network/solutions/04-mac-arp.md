# Q6：MAC 寻址与 ARP 协议（占 10%）

## 题型说明

本题考察**数据链路层的寻址机制**：
- MAC 地址的结构与作用
- ARP 协议的工作过程
- ARP 缓存与 ARP 表
- 数据帧在局域网中的传递过程

---

## 核心知识点一：MAC 地址基础

### 什么是 MAC 地址？

**MAC（Media Access Control）地址** 是网络接口卡（NIC）的**物理地址**，用于数据链路层的帧寻址。

### MAC 地址格式

```
AA:BB:CC:DD:EE:FF
├──────┤├──────┤
  OUI     设备序号
(厂商标识)  (唯一编号)
```

| 特性 | 说明 |
|------|------|
| 长度 | 48位（6字节） |
| 表示 | 十六进制，冒号或连字符分隔 |
| 前3字节 | OUI（组织唯一标识符） → 标识厂商 |
| 后3字节 | 设备序号 → 厂商自行分配 |
| 唯一性 | 全球唯一（理论上） |
| 烧录位置 | 网卡ROM中 |

### 特殊 MAC 地址

| 地址 | 含义 |
|------|------|
| FF:FF:FF:FF:FF:FF | **广播地址**，发送给同一网络所有设备 |
| 01:xx:xx:xx:xx:xx | 多播地址（第一字节最低位=1） |

### MAC 地址 vs IP 地址

| 维度 | MAC 地址 | IP 地址 |
|------|---------|---------|
| 层级 | 数据链路层（L2） | 网络层（L3） |
| 作用范围 | 本地局域网（一跳） | 全网端到端 |
| 是否变化 | 固定不变（硬件绑定） | 可变（根据网络分配） |
| 类比 | 身份证号（固定） | 家庭地址（可变） |
| 长度 | 48位 | 32位（IPv4） |

## 核心知识点二：ARP 协议（Address Resolution Protocol）

### ARP 的作用

**ARP 的核心功能**：已知目标的 **IP 地址**，解析其对应的 **MAC 地址**。

> 为什么需要 ARP？因为数据链路层传输帧时需要 MAC 地址，但上层只知道 IP 地址。

### ARP 工作流程

#### 典型题目
> Explain the ARP process when Host A wants to communicate with Host B on the same network.

#### 图示

```
网络: 192.168.1.0/24

Host A                                    Host B
IP: 192.168.1.10                          IP: 192.168.1.20
MAC: AA:AA:AA:AA:AA:AA                    MAC: BB:BB:BB:BB:BB:BB

Step 1: A 检查 ARP 缓存
        → 缓存中无 B 的 MAC 地址

Step 2: A 发送 ARP Request（广播）
┌───────────────────────────────────────────────────────┐
│ 源MAC: AA:AA:AA:AA:AA:AA                              │
│ 目标MAC: FF:FF:FF:FF:FF:FF（广播）                      │
│ 内容: "谁的IP是 192.168.1.20？请告诉 192.168.1.10"    │
└───────────────────────────────────────────────────────┘
        → 同一网络内所有设备都收到此广播

Step 3: B 收到 ARP Request，发现是询问自己
        → B 记录 A 的 IP-MAC 映射到自己的 ARP 缓存

Step 4: B 发送 ARP Reply（单播）
┌───────────────────────────────────────────────────────┐
│ 源MAC: BB:BB:BB:BB:BB:BB                              │
│ 目标MAC: AA:AA:AA:AA:AA:AA（单播给A）                  │
│ 内容: "192.168.1.20 的 MAC 是 BB:BB:BB:BB:BB:BB"     │
└───────────────────────────────────────────────────────┘

Step 5: A 收到 ARP Reply
        → A 记录 B 的 IP-MAC 映射到 ARP 缓存
        → A 现在可以用 B 的 MAC 地址封装数据帧发送
```

### ARP 过程总结表

| 步骤 | 动作 | 类型 | 说明 |
|------|------|------|------|
| 1 | 检查ARP缓存 | 本地操作 | 查看是否已有目标MAC |
| 2 | 发送ARP Request | **广播** | 目标MAC=FF:FF:FF:FF:FF:FF |
| 3 | 目标主机识别 | 接收处理 | 匹配自己IP的才回复 |
| 4 | 发送ARP Reply | **单播** | 直接发给请求方 |
| 5 | 更新ARP缓存 | 本地操作 | 双方都更新缓存 |

> **关键区分**：ARP Request 是**广播**，ARP Reply 是**单播**。

## 核心知识点三：跨子网的 ARP

### 典型题目
> Host A (192.168.1.10) wants to send data to Host C (10.0.0.5) on a different network. Explain the ARP process.

### 跨网段通信的 ARP 过程

```
子网1: 192.168.1.0/24        路由器         子网2: 10.0.0.0/24
                         ┌─────────┐
Host A ──────────────────│ R       │────────────── Host C
192.168.1.10             │ .1  │.1 │              10.0.0.5
MAC: AA                  │ MAC:R1│R2│              MAC: CC
                         └─────────┘
```

| 步骤 | 动作 | 帧的MAC地址 |
|------|------|-------------|
| 1 | A 发现目标不在同一子网 | - |
| 2 | A 对**默认网关**做 ARP | ARP Request: 谁是 192.168.1.1? |
| 3 | 路由器回复网关MAC | ARP Reply: R1 |
| 4 | A 发送数据帧到路由器 | 源MAC=AA, 目标MAC=**R1** |
| 5 | 路由器收到，查路由表 | 确定从另一接口转发 |
| 6 | 路由器对 C 做 ARP | ARP Request: 谁是 10.0.0.5? |
| 7 | C 回复 MAC | ARP Reply: CC |
| 8 | 路由器转发数据帧到 C | 源MAC=**R2**, 目标MAC=**CC** |

**关键理解**：
- **IP 地址始终不变**：源IP=A的IP，目标IP=C的IP（全程不变）
- **MAC 地址逐跳变化**：每过一个路由器，源MAC和目标MAC都会改变
- 跨网段时，ARP 解析的是**网关的MAC**，不是最终目标的MAC

## 核心知识点四：ARP 缓存

### ARP 缓存表示例

| IP 地址 | MAC 地址 | 类型 | 过期时间 |
|---------|---------|------|---------|
| 192.168.1.1 | R1:R1:R1:R1:R1:R1 | 动态 | 120秒 |
| 192.168.1.20 | BB:BB:BB:BB:BB:BB | 动态 | 85秒 |
| 192.168.1.30 | CC:CC:CC:CC:CC:CC | 静态 | 永不过期 |

**特点**：
- 动态条目有**超时时间**（通常2-20分钟），过期后自动删除
- 静态条目手动配置，永不过期
- 缓存的目的：避免每次通信都进行 ARP 广播

## 核心知识点五：以太网帧结构

### 帧格式

```
┌──────────┬───────────┬───────────┬──────┬─────────┬─────┐
│ Preamble │ Dest MAC  │ Src MAC   │ Type │ Payload │ FCS │
│ (8 bytes)│ (6 bytes) │ (6 bytes) │(2 B) │(46-1500)│(4 B)│
└──────────┴───────────┴───────────┴──────┴─────────┴─────┘
```

| 字段 | 大小 | 功能 |
|------|------|------|
| Preamble | 8字节 | 同步时钟（前导码） |
| Destination MAC | 6字节 | 目标MAC地址 |
| Source MAC | 6字节 | 源MAC地址 |
| Type/Length | 2字节 | 上层协议类型（0x0800=IP, 0x0806=ARP） |
| Payload | 46-1500字节 | 数据（最小46，不足需填充） |
| FCS | 4字节 | 帧校验序列（CRC-32） |

## 综合题目示例

### 题目
> In the network below, Host A (IP: 192.168.1.10, MAC: AA) sends a packet to Host B (IP: 192.168.1.20, MAC: BB). A's ARP cache is empty. Show all frames transmitted.

### 完整解答

**帧1：ARP Request（A → 广播）**
| 字段 | 值 |
|------|------|
| 目标MAC | FF:FF:FF:FF:FF:FF |
| 源MAC | AA:AA:AA:AA:AA:AA |
| Type | 0x0806 (ARP) |
| ARP操作 | Request (1) |
| 发送方IP | 192.168.1.10 |
| 发送方MAC | AA:AA:AA:AA:AA:AA |
| 目标IP | 192.168.1.20 |
| 目标MAC | 00:00:00:00:00:00 (未知) |

**帧2：ARP Reply（B → A，单播）**
| 字段 | 值 |
|------|------|
| 目标MAC | AA:AA:AA:AA:AA:AA |
| 源MAC | BB:BB:BB:BB:BB:BB |
| Type | 0x0806 (ARP) |
| ARP操作 | Reply (2) |
| 发送方IP | 192.168.1.20 |
| 发送方MAC | BB:BB:BB:BB:BB:BB |
| 目标IP | 192.168.1.10 |
| 目标MAC | AA:AA:AA:AA:AA:AA |

**帧3：数据帧（A → B）**
| 字段 | 值 |
|------|------|
| 目标MAC | BB:BB:BB:BB:BB:BB |
| 源MAC | AA:AA:AA:AA:AA:AA |
| Type | 0x0800 (IP) |
| Payload | IP数据报（源IP=192.168.1.10, 目标IP=192.168.1.20） |

## 答题技巧

1. **区分广播与单播**：ARP Request=广播，ARP Reply=单播
2. **跨网段**：先 ARP 网关，MAC 逐跳变化但 IP 不变
3. **帧头填写要完整**：源MAC、目标MAC、Type 字段都不能漏
4. **时间分配**：Q6 占 10%（约 12 分钟），画出帧结构+分步过程
5. **常见陷阱**：跨子网通信中，ARP 解析的不是最终目标而是网关
