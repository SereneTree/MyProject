## 🎯 必背核心考点（Top 15）

> 这 15 题占面试出现率 **80%+**，没复习时间也要先把这些拿下。

| 排名 | 考点 | 一句话答案 |
|------|------|-----------|
| 1 | 为什么用 B+ 树？ | 矮胖 + 范围查询 + 顺序 IO 友好 |
| 2 | 聚簇索引 vs 非聚簇索引 | 聚簇：叶子存数据；非聚簇：叶子存主键，需回表 |
| 3 | 最左前缀原则 | 联合索引 (a,b,c)，必须从 a 开始才能用上索引 |
| 4 | 索引失效场景 | `!=`、`OR`、函数、隐式转换、`%xx`、范围列后续 |
| 5 | 4 种隔离级别 | 读未提交 / 读已提交 / 可重复读 (默认) / 串行化 |
| 6 | 脏读、不可重复读、幻读 | 读未提交数据 / 同事务两次读不同 / 范围查询出现新行 |
| 7 | MVCC 原理 | 版本链 (undo log) + Read View + 当前读/快照读 |
| 8 | InnoDB 如何解决幻读？ | RR 隔离级别 + Next-Key Lock (行锁 + 间隙锁) |
| 9 | 行锁 vs 表锁 | 行锁加在索引记录；走不到索引会退化为表锁 |
| 10 | 乐观锁 vs 悲观锁 | 乐观锁=version 字段；悲观锁=`SELECT ... FOR UPDATE` |
| 11 | redo / undo / binlog | 崩溃恢复 / 回滚+MVCC / 主从复制+归档 |
| 12 | 慢查询如何排查？ | 慢日志 → EXPLAIN → 索引/SQL 重写 |
| 13 | 大表分页优化 | 延迟关联 / 子查询 / 游标分页 |
| 14 | 分库分表策略 | 水平拆分 (按用户ID) / 垂直拆分 (按字段) |
| 15 | 主从延迟原因 | 单线程 SQL 回放 / 大事务 / 网络抖动 |

## 🗣️ 答题黄金三段式

任何 MySQL 面试题都可以用这个模板回答：

```
【是什么】 概念定义 + 关键字
   ↓
【为什么】 设计原因 + 解决了什么问题
   ↓
【怎么用】 业务场景 + 代码/SQL 示例
```

**示例**：「为什么 InnoDB 用 B+ 树而不是 B 树？」

> **【是什么】** B+ 树是一种平衡多路查找树，所有数据都存在叶子节点，且叶子节点之间通过指针相连。
>
> **【为什么】** 相比 B 树，B+ 树有三大优势：1）非叶子节点不存数据，单页能存更多键，树高度更低，磁盘 IO 更少；2）叶子节点链表，范围查询不需要中序遍历；3）查询稳定，每次查询都走到叶子，性能可预期。
>
> **【怎么用】** InnoDB 的聚簇索引就是 B+ 树，主键查询走聚簇索引、二级索引查询则需要回表。比如 `SELECT * FROM user WHERE id = 100` 走 1-3 次磁盘 IO 就能找到数据。

## 📝 复习心法

1. **不背孤立知识点**：所有概念都要联系到「**为什么这样设计**」
2. **画图理解**：B+ 树、版本链、锁示意图，自己画一遍胜过看十遍
3. **手写 SQL**：每个隔离级别、每种锁，至少手写一个验证 SQL
4. **结构化输出**：面试时按「是什么 → 为什么 → 怎么用」三段式作答
5. **关联实际场景**：学完一个知识点，问自己「我项目里哪里用得上？」
