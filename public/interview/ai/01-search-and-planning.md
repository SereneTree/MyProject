# 搜索与规划 —— 面试高频考点

> 搜索是 AI 的基石。面试中常考搜索算法的选择依据、复杂度分析、启发式设计。

---

## 一、核心知识框架

```
搜索问题定义
├── 状态空间 (State Space)
├── 初始状态 (Initial State)
├── 动作集合 (Actions)
├── 转移模型 (Transition Model)
├── 目标测试 (Goal Test)
└── 路径代价 (Path Cost)

搜索策略分类
├── 无信息搜索 (Uninformed)
│   ├── BFS (广度优先)
│   ├── DFS (深度优先)
│   ├── UCS (一致代价)
│   └── IDS (迭代加深)
└── 有信息搜索 (Informed)
    ├── Greedy Best-First
    ├── A*
    └── IDA*
```

## 二、算法对比速查表

| 算法 | 策略 | 完备性 | 最优性 | 时间 | 空间 | 适用场景 |
|------|------|--------|--------|------|------|---------|
| BFS | FIFO队列，按层扩展 | ✅ | ✅(等权) | O(b^d) | O(b^d) | 等权图最短路径 |
| DFS | LIFO栈，深入优先 | ❌(无限图) | ❌ | O(b^m) | O(bm) | 内存受限、解存在性判断 |
| UCS | 优先队列，按g(n)排序 | ✅ | ✅ | O(b^(C*/ε)) | O(b^(C*/ε)) | 边权不等的最短路径 |
| IDS | 逐步加深DFS | ✅ | ✅(等权) | O(b^d) | O(bd) | BFS最优性+DFS低空间 |
| Greedy | 按h(n)排序 | ❌ | ❌ | O(b^m) | O(b^m) | 快速找到可行解 |
| **A*** | 按f(n)=g(n)+h(n)排序 | ✅ | ✅(h可容许) | O(b^d) | O(b^d) | 有好启发式的最短路径 |

> b=分支因子, d=最优解深度, m=状态空间最大深度, C*=最优解代价, ε=最小步代价

## 三、重点考点深入

### 考点1：A*算法

**核心公式**：f(n) = g(n) + h(n)
- g(n)：从起点到节点n的已知最短路径代价
- h(n)：从n到目标的启发式估计代价
- f(n)：经过n的路径总代价估计

**最优性条件**：
- **可容许(Admissible)**：h(n) ≤ h*(n)（不高估真实代价）
- **一致性(Consistent)**：h(n) ≤ c(n,a,n') + h(n')（三角不等式）

**面试常问**：
```
Q: 为什么一致性比可容许性更强？
A: 一致性 ⇒ 可容许性（逆命题不成立）
   一致性保证 f(n) 沿路径单调递增
   → A* 扩展一个节点时就已经找到了到它的最短路径
   → 不需要重新打开已关闭的节点，效率更高
```

**经典启发式示例**：
| 问题 | 启发式h(n) | 可容许？ |
|------|-----------|---------|
| 网格最短路径 | 曼哈顿距离 | ✅ (不能穿墙) |
| 网格最短路径 | 欧氏距离 | ✅ (直线≤实际路径) |
| 8-puzzle | 错位数(misplaced tiles) | ✅ (至少移动错位数次) |
| 8-puzzle | 曼哈顿距离之和 | ✅ (更紧的估计) |

### 考点2：图搜索 vs 树搜索

| 对比项 | 树搜索 | 图搜索 |
|--------|--------|--------|
| 重复检测 | 不检测 | 维护 explored/closed set |
| 死循环风险 | 有（可能无限循环） | 无 |
| 空间开销 | 较低 | 较高（需存储已访问集合） |
| A*最优性条件 | h可容许即可 | 需要h一致（或允许reopen） |

**面试高频问**：
```
Q: 什么时候用树搜索更好？
A: 1. 状态空间是树形结构（无环），如博弈树
   2. 状态空间巨大但解的深度有限，存储explored set不划算
   3. 使用IDA*等迭代加深策略时
```

### 考点3：启发式设计原则

**好启发式的标准**：
1. **可容许**：保证最优性
2. **尽量紧**：h(n)越接近h*(n)越好，扩展节点越少
3. **高效计算**：O(1)时间内可算出

**松弛法（Relaxation）设计启发式**：
```
原问题约束: 滑块只能移动到相邻空位
松弛1: 滑块可以移到任意空位 → 错位数
松弛2: 滑块可以移到相邻任意位置（无空位限制）→ 曼哈顿距离

松弛越少 → 启发式越紧 → 搜索效率越高
```

**组合启发式**：
```
h(n) = max(h1(n), h2(n), ..., hk(n))
若每个hi都可容许，则max也可容许，且更紧
```

## 四、典型面试题 & 答案

### 题1：比较BFS和DFS的优劣

**答**：
- **BFS优势**：完备（有限图一定找到解）、最优（等权下最短路径）
- **BFS劣势**：空间 O(b^d)，对于大分支因子内存爆炸
- **DFS优势**：空间仅 O(bm)，适合深度有限的搜索
- **DFS劣势**：不完备（可能陷入无限分支）、非最优
- **折中方案**：IDS（迭代加深）= BFS的最优性 + DFS的低空间

### 题2：为什么A*是最优的有信息搜索？

**答**：
1. 可容许启发式保证 h(n) ≤ h*(n)
2. 因此 f(n) = g(n) + h(n) ≤ g(n) + h*(n) = f*(n)（真实最优代价）
3. A* 扩展的是 f 值最小的节点
4. 在扩展目标节点时，所有 f 值 ≤ f(goal) 的节点都已被扩展
5. 由于 f(goal) = g(goal)（h(goal)=0），这就是最优解的代价

### 题3：设计一个搜索问题的状态空间

**答题模板**：
```
问题: [描述]

初始状态: [起始配置]
动作: [合法操作集合]
转移模型: [动作如何改变状态]
目标测试: [什么条件算成功]
路径代价: [如何衡量代价]
状态空间大小: [估算]
```

### 题4：A*的时间复杂度为什么仍然可能很高？

**答**：
- 最坏情况下（h=0退化为UCS），时间 O(b^d)，与BFS相同
- 实际性能取决于启发式质量：h越接近h*，搜索越少节点
- **有效分支因子 b***：实际扩展节点数 N ≈ (b*)^d，好的启发式让 b* 接近1

## 五、面试加分点

### 实际应用举例

| 搜索算法 | 工业应用 |
|---------|---------|
| A* | 游戏NPC寻路、地图导航（Google Maps） |
| BFS/DFS | 社交网络关系搜索、网页爬虫 |
| IDA* | 魔方求解器（内存受限的最优搜索） |
| 双向搜索 | 社交网络中两人最短关系链 |

### 常见追问与应对

```
Q: A*和Dijkstra什么关系？
A: Dijkstra = A*(h=0) = UCS，即没有启发式的A*

Q: 如果启发式不可容许会怎样？
A: A*可能找到非最优解，但通常找到的解质量仍然不错
   加权A*: f(n) = g(n) + w·h(n), w>1 牺牲最优性换速度

Q: 实际工程中搜索空间太大怎么办？
A: ① 剪枝（排除明显无效分支）
   ② 局部搜索（爬山、模拟退火）
   ③ 分层规划（先粗粒度再细粒度）
   ④ 双向搜索（从起点和终点同时搜索）
```
