# 博弈与对抗搜索 —— 面试高频考点

> 对抗搜索是面试中"手推算法"的重灾区，α-β剪枝几乎必考。核心是理解博弈双方理性假设下的决策逻辑。

---

## 一、核心知识框架

```
博弈类型
├── 确定性完全信息博弈 → Minimax
├── 不确定性博弈（对手非最优）→ Expectimax
├── 不完全信息博弈 → 蒙特卡洛树搜索(MCTS)
└── 多人博弈 → 多方Minimax（联盟/非零和）

对抗搜索算法
├── Minimax（暴力搜索）
├── α-β剪枝（Minimax加速）
├── Expectimax（概率对手）
├── 蒙特卡洛树搜索(MCTS)
└── 评估函数设计
```

---

## 二、算法对比速查表

| 算法 | 对手假设 | 时间复杂度 | 空间复杂度 | 适用场景 |
|------|---------|-----------|-----------|---------|
| Minimax | 完全理性（最优对手） | O(b^m) | O(bm) | 象棋、围棋、井字棋 |
| α-β剪枝 | 完全理性 | O(b^(m/2)) 最优 | O(bm) | Minimax加速 |
| Expectimax | 随机/非最优对手 | O(b^m) | O(bm) | 骰子游戏、不确定对手 |
| MCTS | 未知（通过模拟估计） | 可控 | 可控 | 围棋、状态空间极大 |

> b=分支因子, m=博弈树深度

## 三、重点考点深入

### 考点1：Minimax算法

**核心思想**：
```
MAX玩家: 选择使评估值最大化的动作（自己）
MIN玩家: 选择使评估值最小化的动作（对手）
交替递归直到终局或深度限制
```

**伪代码**：
```
function minimax(state, depth, isMaxPlayer):
    if depth == 0 or state is terminal:
        return evaluate(state)
    
    if isMaxPlayer:
        value = -∞
        for each child of state:
            value = max(value, minimax(child, depth-1, false))
        return value
    else:
        value = +∞
        for each child of state:
            value = min(value, minimax(child, depth-1, true))
        return value
```

**面试常问**：
```
Q: Minimax的前提假设是什么？
A: 1. 零和博弈（一方得=另一方失）
   2. 双方完全理性（都做最优选择）
   3. 完全信息（双方知道所有状态）

Q: 如果对手不是最优的怎么办？
A: Minimax仍然安全（保证最坏情况下的最好结果）
   但可能过于保守，错过利用对手弱点的机会
   → 改用Expectimax（假设对手以概率分布行动）
```

### 考点2：α-β剪枝（必考手推）

**核心思想**：在Minimax搜索中跳过不可能影响最终决策的分支。

**关键定义**：
- **α**：MAX节点目前能保证的最小收益（MAX的下界）
- **β**：MIN节点目前能保证的最大损失（MIN的上界）
- **剪枝条件**：α ≥ β 时剪枝

**剪枝规则**：
```
在MAX节点:
  更新 α = max(α, 子节点值)
  如果 α ≥ β → 剪掉剩余子节点（MIN不会选择这个分支）

在MIN节点:
  更新 β = min(β, 子节点值)
  如果 α ≥ β → 剪掉剩余子节点（MAX不会选择这个分支）
```

**手推示例**：
```
         MAX
        / | \
      MIN MIN MIN
      /\  /\  /\
     3 5 6 2 1 8

步骤:
1. 左MIN: min(3,5) = 3 → MAX的α更新为3
2. 中MIN: 先看6，β=6; 再看2，β=min(6,2)=2
   此时 α=3 ≥ β=2 → 不剪枝（已遍历完）
   中MIN值=2，MAX不更新α（2<3）
3. 右MIN: 先看1，β=1
   此时 α=3 ≥ β=1 → 剪枝！不再看8
   
MAX最终选择左分支，值=3
```

**最优排序下的效率**：
```
最好情况: 完美排序 → O(b^(m/2))（相当于搜索深度翻倍）
最差情况: 逆序排列 → O(b^m)（无剪枝，退化为Minimax）
实际效果: 通常能搜索深度增加约75%
```

### 考点3：Expectimax

**与Minimax的区别**：
```
Minimax:  MAX层取max，MIN层取min
Expectimax: MAX层取max，CHANCE层取期望值(加权平均)
```

**公式**：
```
CHANCE节点的值 = Σ P(outcome) × Value(outcome)
```

**关键面试问题**：
```
Q: 为什么α-β剪枝不能用于Expectimax？
A: α-β依赖于"如果这个分支比已知选项差，对手一定会选它"
   但CHANCE节点取期望，一个子节点值很低不意味着整体期望低
   （可能另一个子节点值非常高，拉高了期望）
   因此不能安全地剪枝

Q: Expectimax什么时候优于Minimax？
A: 当对手不是最优的时候：
   - 对手随机行动（掷骰子）
   - 对手是初学者（以概率犯错）
   - 环境有随机性（天气、噪声）
```

### 考点4：评估函数设计

当搜索深度有限时，需要**评估函数**估算非终局状态的好坏：

**设计原则**：
```
1. 终局正确: 终局状态评估=真实胜负值
2. 计算高效: O(1)时间可算出
3. 与胜率正相关: 评估值越高，实际获胜概率越大
4. 特征组合: eval(s) = w1·f1(s) + w2·f2(s) + ... + wn·fn(s)
```

**象棋评估函数示例**：
```
eval(s) = 9×(我方皇后-对方皇后) 
         + 5×(我方车-对方车)
         + 3×(我方马/象-对方马/象)
         + 1×(我方兵-对方兵)
         + 位置奖励（控制中心、王安全）
```

## 四、典型面试题 & 答案

### 题1：手推α-β剪枝过程

**答题技巧**：
1. 画出博弈树，标注MAX/MIN层
2. 从左到右DFS遍历
3. 每个节点标注当前(α, β)
4. 满足 α ≥ β 时标记"剪枝"
5. 说明哪些节点不需要访问

### 题2：为什么α-β剪枝不影响最终结果？

**答**：
- 被剪掉的分支有两种情况：
  1. **MAX节点的β剪枝**：MIN父节点已知有值≤β的选项，即使这个子树有更大值，MIN也不会选它
  2. **MIN节点的α剪枝**：MAX父节点已知有值≥α的选项，即使这个子树有更小值，MAX也不会选它
- 本质：被剪掉的分支**不可能被理性对手允许到达**
- 因此最终决策与完整Minimax一致

### 题3：Minimax/Expectimax/MCTS分别适合什么场景？

**答**：

| 算法 | 适用场景 | 不适用场景 |
|------|---------|-----------|
| Minimax+αβ | 确定性零和完全信息（象棋、五子棋） | 状态空间太大、对手不理性 |
| Expectimax | 有随机性（骰子）或对手非最优 | 计算量大无法深搜 |
| MCTS | 状态空间极大（围棋）、评估函数难设计 | 需要精确最优解 |

### 题4：如何提升α-β剪枝的效率？

**答**：
1. **移动排序**：先搜索"看起来好"的子节点（启发式排序）→ 更早建立好的α/β → 更多剪枝
2. **迭代加深**：用浅层搜索结果排序深层搜索的节点
3. **Killer Move**：记录之前导致剪枝的动作，优先搜索
4. **转置表**：缓存已评估状态的值，避免重复计算（特别是棋类中换位）
5. **Aspiration Window**：用窄窗搜索，失败时再扩大

## 五、面试加分点

### 实际应用举例

| 算法 | 工业应用 |
|------|---------|
| Minimax+αβ | IBM Deep Blue（国际象棋）、五子棋AI |
| MCTS | AlphaGo（围棋）、游戏AI（Poker、RTS） |
| Expectimax | 2048游戏AI、西洋双陆棋（含骰子） |

### 常见追问与应对

```
Q: AlphaGo用的什么算法？
A: MCTS + 深度神经网络（策略网络+价值网络）
   策略网络指导搜索方向（先搜好的动作）
   价值网络替代随机rollout（直接评估局面）
   本质仍是搜索+评估，只是用DL替代了手工评估函数

Q: 如何判断一个游戏适合用Minimax还是MCTS？
A: 分支因子小(b<40) + 有好的评估函数 → Minimax+αβ
   分支因子大(b>100) + 难设计评估函数 → MCTS
   有随机性 → Expectimax 或 MCTS with chance nodes

Q: 零和博弈和非零和博弈的区别？
A: 零和：一方得分=另一方失分（象棋、围棋）
   非零和：双方可能共赢或共输（囚徒困境、合作博弈）
   非零和不能用标准Minimax，需要纳什均衡等博弈论方法
```
