## 二、ARP 协议（必背）

### ARP 工作原理

**目的**：已知目标IP地址，查询其MAC地址。

```
场景: 主机A(192.168.1.10)要发送数据给主机B(192.168.1.20)
      A知道B的IP但不知道B的MAC地址

步骤:
① A检查本地ARP缓存 → 没有B的MAC记录

② A广播ARP请求 (目的MAC=FF:FF:FF:FF:FF:FF):
   "谁的IP是192.168.1.20？请告诉192.168.1.10"
   
③ 同网段所有主机收到 → 只有B(192.168.1.20)回应

④ B单播ARP应答给A:
   "我是192.168.1.20，我的MAC是BB:BB:BB:BB:BB:BB"

⑤ A将映射(192.168.1.20 → BB:BB:BB:BB:BB:BB)存入ARP缓存
   后续直接查缓存，无需再次广播
```

### 跨网段通信中的ARP

```
A(192.168.1.10) → 路由器(192.168.1.1) → B(10.0.0.20)

关键: A发现B不在同一子网 → ARP查的是网关(路由器)的MAC!

帧1 (A→路由器):
  源MAC=A的MAC, 目的MAC=路由器的MAC
  源IP=A的IP,   目的IP=B的IP

帧2 (路由器→B):
  源MAC=路由器的MAC, 目的MAC=B的MAC
  源IP=A的IP,        目的IP=B的IP

结论: IP地址全程不变(端到端)，MAC地址逐跳改变(点到点)
```

## 三、以太网帧格式

```
┌──────────┬──────────┬──────┬──────────────────┬─────┐
│ 目的MAC  │  源MAC   │ 类型 │     数据(IP包)    │ FCS │
│  6字节   │  6字节   │2字节 │   46~1500字节    │4字节│
└──────────┴──────────┴──────┴──────────────────┴─────┘

类型字段(EtherType):
  0x0800 = IPv4
  0x0806 = ARP
  0x86DD = IPv6

MTU = 1500字节 (以太网最大载荷)
最小帧长 = 64字节 (填充至46字节数据)
```

## 四、CSMA/CD（以太网冲突检测）

```
CSMA/CD = Carrier Sense Multiple Access with Collision Detection
          载波侦听   多路访问      冲突检测

工作流程:
1. 先听后发(Carrier Sense): 发送前检测信道是否空闲
2. 边发边听(Collision Detection): 发送时检测是否有冲突
3. 检测到冲突 → 发送干扰信号(Jam) → 停止发送
4. 退避等待: 二进制指数退避算法（等待随机时间后重试）
   第k次冲突: 随机等待 [0, 2^k - 1] × 时隙时间

适用: 半双工以太网(Hub连接)
不适用: 全双工交换式以太网(现代网络) → 无冲突
```

## 五、交换机 vs 路由器 vs 集线器

| 对比 | 集线器(Hub) | 交换机(Switch) | 路由器(Router) |
|------|------------|---------------|---------------|
| 工作层次 | L1 物理层 | L2 链路层 | L3 网络层 |
| 转发依据 | 无（广播所有端口） | MAC地址表 | IP路由表 |
| 冲突域 | 所有端口共享 | 每个端口独立 | 每个端口独立 |
| 广播域 | 一个广播域 | 一个广播域 | 隔离广播域 |
| 智能程度 | 无 | 学习MAC自动转发 | 路由选择+NAT等 |

### 交换机工作原理

```
交换机MAC地址表(自学习):

端口 | MAC地址        | 动作
P1   | AA:AA:AA:...  | 记录: 从P1口学到A的MAC
P2   | BB:BB:BB:...  | 记录: 从P2口学到B的MAC
P3   | (未知)         |

转发逻辑:
1. 收到帧 → 记录 源MAC↔端口 映射
2. 查表: 目的MAC对应哪个端口？
   - 找到 → 从该端口转发(单播)
   - 未找到 → 从所有其他端口泛洪(Flooding)
   - 目的MAC=广播 → 泛洪

自学习过程: 随着通信进行，表自动建立完善
超时机制: 长时间无活动的条目被老化删除
```

## 六、典型面试题 & 答案

### 题1：ARP的作用和工作过程？

**答**：ARP(地址解析协议)用于将已知的IP地址映射为对应的MAC地址。

**过程**：
1. 发送方先查本地ARP缓存
2. 缓存未命中 → 在本网段广播ARP请求（"谁的IP是x.x.x.x"）
3. 拥有该IP的主机单播ARP应答（回复自己的MAC地址）
4. 发送方缓存该映射，后续直接使用

**补充**：如果目标不在同一子网，ARP请求的目标IP是**默认网关**的IP，而非最终目的IP。

### 题2：交换机和路由器的区别？

**答**：
- **交换机(L2)**：根据MAC地址在同一网络内部转发帧，不能跨子网通信
- **路由器(L3)**：根据IP地址在不同网络之间路由转发，可以跨子网、支持NAT

关键区别：
- 交换机不隔离广播域（广播帧会泛洪到所有端口）
- 路由器隔离广播域（广播不跨路由器）
- 交换机靠自学习建MAC表，路由器靠路由协议建路由表

### 题3：为什么以太网帧有最小长度(64字节)？

**答**：与CSMA/CD冲突检测有关。发送方需要在发送帧的过程中检测到可能的冲突。

如果帧太短，发送方可能在冲突信号到达之前就已经发完帧，以为发送成功了。

最小帧长 = 2 × 最大传播延迟 × 带宽 = 保证发送期间能检测到最远端的冲突。

对于10Mbps以太网：最小帧=64字节，对应512比特时间=51.2μs=信号往返时间。

### 题4：VLAN的作用是什么？

**答**：VLAN(虚拟局域网)在一台物理交换机上划分出多个逻辑上隔离的广播域。

**好处**：
1. 隔离广播：减少不必要的广播流量
2. 安全隔离：不同VLAN间不能直接通信（需经路由器）
3. 灵活管理：不受物理位置限制，逻辑分组

**实现**：802.1Q在以太网帧中插入4字节VLAN Tag(包含VLAN ID)。

## 八、面试加分点

### 常见追问与应对

```
Q: ARP欺骗/攻击原理？
A: 攻击者发送虚假ARP应答，将网关IP映射为自己的MAC
   → 受害者流量都经过攻击者(中间人攻击)
   防御: 静态ARP绑定、动态ARP检测(DAI)、802.1X认证

Q: 广播风暴怎么产生？怎么解决？
A: 交换机环路导致广播帧无限循环泛洪
   解决: STP(生成树协议)——逻辑上断开环路，保持树形拓扑

Q: 半双工和全双工的区别？
A: 半双工: 同一时刻只能单向通信(对讲机) → 需要CSMA/CD
   全双工: 可以同时双向通信(电话) → 无冲突，不需要CSMA/CD
   现代交换式以太网都是全双工
```
