## 一、业务痛点

### 1.1 为什么需要复杂网络？

微信的核心是**社交关系图谱**——每个用户是一个节点，好友关系是一条边。以下业务场景离不开复杂网络分析：

| 场景 | 痛点 | 网络视角 |
|------|------|---------|
| 好友推荐"你可能认识的人" | 如何从数十亿用户中找到真正可能认识的人？ | 二阶邻居 + 共同好友数 |
| 群组/兴趣圈推荐 | 如何发现用户所在的社交圈子？ | 社区检测算法 |
| 朋友圈信息流排序 | 谁的朋友圈动态对我更重要？ | 社交亲密度 + 互动网络中心性 |
| 账号安全与反欺诈 | 如何识别批量注册的虚假账号群？ | 异常子图检测 |

### 1.2 业务规模数据

```
用户节点数:         ~13 亿
好友关系边数:       ~千亿（估计平均好友数150+）
日均消息数:         ~450 亿条
朋友圈日活跃:       ~7.8 亿
```

## 二、网络建模

### 2.1 图的定义

```
G = (V, E, W)

V: 用户集合（每个微信ID为一个节点）
E: 好友关系集合（无向边，双向互为好友）
W: 边权重 = f(聊天频率, 共同群数, 朋友圈互动次数, 通讯录关系)
```

### 2.2 多层网络设计

微信实际使用**多层网络（Multiplex Network）**建模：

```
Layer 1: 好友关系网络（静态，无向）
   └── 节点属性: 年龄、城市、注册时间
   └── 边属性: 添加时间、共同好友数

Layer 2: 通讯互动网络（动态，有向加权）
   └── 边权重: 近30天消息数 + 语音/视频通话时长
   └── 方向: A→B 的消息量可能 ≠ B→A

Layer 3: 群组共现网络（二部图 → 投影）
   └── 用户-群组二部图 → 投影为用户-用户共同群数

Layer 4: 朋友圈互动网络（有向加权）
   └── 点赞、评论、转发行为构成的有向边
```

### 2.3 存储架构

| 层 | 存储方案 | 原因 |
|----|---------|------|
| 好友关系 | 分布式图数据库 (Plato/自研) | 亿级节点+千亿边，需支持高并发读 |
| 互动网络 | 时序数据库 + 滑动窗口 | 动态衰减，近期互动权重更高 |
| 实时计算 | 图计算引擎 (类 Pregel) | 分布式消息传递，并行BFS/PageRank |

## 三、核心算法与分析方法

### 3.1 小世界网络特性验证

**发现**：微信网络呈现典型的小世界特性

| 指标 | 微信网络 | ER随机图(同规模) | 解释 |
|------|---------|----------------|------|
| 平均路径长度 L | ~4.5 | ~5.0 | "四度分隔"，比六度更短 |
| 聚集系数 C | ~0.6 | ~0.0001 | 远高于随机图→朋友的朋友大概率也是朋友 |
| 度分布 | 幂律 P(k)∝k^(-γ) | 泊松 | 存在超级节点（公众号、大V） |

**应用**：高聚集系数直接支撑"共同好友推荐"的有效性——如果A和B有多个共同好友，他们大概率互相认识。

### 3.2 社区检测：Louvain 算法优化

**目标**：发现用户的社交圈子（同事群、大学同学、家人等）

```python
# Louvain算法核心思想：最大化模块度(Modularity)
# Q = (1/2m) * Σ[Aij - ki*kj/(2m)] * δ(ci, cj)

# 微信改进版：加入边权重和时间衰减
def weighted_modularity_gain(node_i, community_c, G):
    """计算节点i加入社区c的模块度增益（带权重版本）"""
    # 节点i与社区c内节点的加权连接之和
    sigma_in = sum(G[node_i][j]['weight'] for j in community_c if G.has_edge(node_i, j))
    # 社区c的总加权度
    sigma_tot = sum(G.degree(n, weight='weight') for n in community_c)
    # 节点i的加权度
    k_i = G.degree(node_i, weight='weight')
    # 全图总权重
    m = G.size(weight='weight')
    
    delta_Q = sigma_in/m - (sigma_tot * k_i) / (2 * m**2)
    return delta_Q
```

**工程优化（应对13亿节点）**：
1. **分布式 Louvain**：将图按地域分片，各片内先做本地社区检测，再跨片合并
2. **增量更新**：新加好友时只重新计算受影响的局部社区，而非全图重跑
3. **层次聚合**：先做一轮粗粒度聚合(超节点)，再在超图上精细聚类

### 3.3 好友推荐：基于网络拓扑的排序

```python
def recommend_friends(user, G, top_k=10):
    """基于网络拓扑特征的好友推荐"""
    candidates = {}
    
    # 获取二阶邻居（朋友的朋友）
    friends = set(G.neighbors(user))
    for friend in friends:
        for fof in G.neighbors(friend):
            if fof != user and fof not in friends:
                if fof not in candidates:
                    candidates[fof] = {'common_friends': 0, 'adamic_adar': 0}
                candidates[fof]['common_friends'] += 1
                # Adamic-Adar指数：共同好友的度越小，推荐权重越大
                candidates[fof]['adamic_adar'] += 1 / np.log(G.degree(fof))
    
    # 综合评分
    scores = {}
    for candidate, features in candidates.items():
        score = (0.6 * features['common_friends'] + 
                 0.3 * features['adamic_adar'] +
                 0.1 * jaccard_coefficient(user, candidate, G))
        scores[candidate] = score
    
    # 返回Top-K
    return sorted(scores.items(), key=lambda x: x[1], reverse=True)[:top_k]
```

**常用链接预测指标**：

| 指标 | 公式 | 适用场景 |
|------|------|---------|
| 共同好友数 | \|N(x) ∩ N(y)\| | 最直观，计算快 |
| Jaccard系数 | \|N(x)∩N(y)\| / \|N(x)∪N(y)\| | 消除度数差异影响 |
| Adamic-Adar | Σ 1/log(k_z), z∈N(x)∩N(y) | 稀有共同好友权重更大 |
| Resource Allocation | Σ 1/k_z, z∈N(x)∩N(y) | 类似AA，惩罚力度更大 |

### 3.4 社交亲密度与信息流排序

```
亲密度 S(A,B) = α·chat_freq + β·call_duration + γ·moment_interaction + δ·common_groups
                + ε·f(time_decay)

其中 time_decay = exp(-λ·Δt)，Δt为距上次互动的天数
```

朋友圈信息流排序：使用 **PersonalRank** (个性化 PageRank) 在互动网络上传播，离用户"社交距离"近的好友动态排名更靠前。

## 四、技术亮点

### 亮点 1：亿级图上的实时社区发现

| 挑战 | 解决方案 |
|------|---------|
| 13亿节点 Louvain 全量计算需数小时 | 分布式图计算引擎(类Pregel)，分片并行 |
| 每天新增/删除好友关系 | 增量社区更新：只重算受影响的边界节点 |
| 社区粒度不确定 | 多尺度社区：从2-3人小圈到百人同学群都能识别 |

### 亮点 2：多层网络融合提升推荐精度

单层好友关系推荐准确率 ~40%，融合4层网络后：
- 好友关系 + 互动频率 → 区分"活跃好友"vs"僵尸好友"
- 加入群组共现 → 发现同事/同学等组织关系
- 加入朋友圈互动 → 捕捉单向关注的"弱关系"
- 综合后推荐准确率提升至 ~72%

### 亮点 3：利用聚集系数做反欺诈

正常用户的好友网络聚集系数高（朋友之间互相认识），而批量注册的虚假账号：
- 彼此之间互加好友（形成完全图/近完全图）
- 与外部正常用户的连接极少
- 聚集系数异常高 + 社区间连接异常低 → 检测信号

### 可复用的设计模式

```
模式1: 多层网络融合
适用场景: 任何需要综合多种关系的推荐/分类任务
实现思路: 各层独立计算特征 → 特征加权融合 → 统一排序

模式2: 增量社区更新
适用场景: 大规模图的动态社区维护
实现思路: 维护社区归属表 → 边变化时检查边界节点 → 局部重计算

模式3: 图拓扑特征做异常检测
适用场景: 反作弊、反欺诈、虚假账号识别
实现思路: 计算局部图指标(聚集系数/子图密度) → 与正常分布对比 → 异常标记
```
