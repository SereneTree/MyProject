| 维度 | 信息 |
|------|------|
| 企业 | Google |

| 规模 | 知识图谱包含超过 5000 亿事实(Facts)，覆盖 50 亿+实体 |

## 一、业务痛点

### 1.1 为什么需要图结构？

传统搜索引擎基于**关键词匹配**——用户输入关键词，引擎返回包含该词的网页。但这无法理解语义：

| 传统搜索的问题 | 图结构的解决方案 |
|--------------|---------------|
| "苹果"是水果还是公司？ | 实体消歧：通过图中的邻居关系判断语境 |
| "谁是乔布斯的妻子？" | 图遍历：从"乔布斯"节点沿"配偶"边直接找到答案 |
| "和贝多芬同时代的画家有谁？" | 多跳推理：贝多芬→出生年代→同时期人物→筛选画家 |
| "推荐类似《三体》的书" | 子图匹配：找与《三体》共享标签/作者风格的实体 |

### 1.2 业务规模

```
实体数量:       ~50 亿(人物、地点、组织、作品、概念...)
事实/三元组:    ~5000 亿 (实体-关系-实体)
支撑搜索量:     每天处理 85 亿次搜索
语义搜索占比:   ~40% 的搜索触发知识面板(Knowledge Panel)
```

## 二、图建模

### 2.1 知识图谱的图表示

```
G = (V, E, L)

V(节点): 实体 — 人物/地点/组织/作品/概念/事件
E(边):   关系 — 有向标记边(labeled directed edge)
L(标签): 节点类型 + 边类型(关系名)

三元组表示: (head, relation, tail)
示例:
  (乔布斯, 创办, 苹果公司)
  (苹果公司, 总部位于, 库比蒂诺)
  (库比蒂诺, 位于, 加利福尼亚州)
  (乔布斯, 出生日期, 1955-02-24)
```

### 2.2 图的特征

| 特征 | 说明 |
|------|------|
| 有向图 | 关系有方向：(A, 创办, B) ≠ (B, 创办, A) |
| 多关系图 | 同一对实体间可有多种关系 |
| 异构图 | 节点有多种类型(人/地/物)，边有多种类型(关系) |
| 稀疏图 | 5000亿边 vs 50亿节点² = 极稀疏 |
| 动态图 | 不断有新实体和关系加入(网页爬取更新) |

### 2.3 存储架构

```
存储层:
┌─────────────────────────────────────────────────┐
│  分布式图数据库 (Bigtable + 自研图引擎)          │
│  - 每个实体一行，列族存储其出边和入边            │
│  - 倒排索引：关系类型→涉及的实体对              │
│  - 向量索引：实体嵌入→近似最近邻搜索            │
└─────────────────────────────────────────────────┘

查询层:
┌─────────────────────────────────────────────────┐
│  图查询引擎                                      │
│  - 多跳遍历(BFS/DFS限深)                        │
│  - 子图模式匹配(SPARQL-like)                    │
│  - 最短路径(实体间最短关系链)                     │
└─────────────────────────────────────────────────┘
```

## 三、核心算法与应用

### 3.1 图遍历——实体关系查询

```python
def answer_factoid_question(kg, question):
    """
    回答事实性问题："谁是X的Y？"
    将自然语言解析为图遍历操作
    """
    # Step 1: 实体识别 — 从问题中提取实体
    entity = extract_entity(question)  # "乔布斯"
    
    # Step 2: 关系识别 — 识别查询的关系类型
    relation = extract_relation(question)  # "妻子/配偶"
    
    # Step 3: 图遍历 — 沿指定关系边遍历
    # 单跳查询：O(1) 邻接表查找
    answer = kg.get_neighbors(entity, relation=relation)
    # 返回: ["劳伦·鲍威尔·乔布斯"]
    
    return answer

def multi_hop_reasoning(kg, start_entity, relation_path):
    """
    多跳推理："贝多芬出生国家的首都是哪里？"
    关系路径: [出生地→所属国家→首都]
    """
    current = start_entity  # "贝多芬"
    for relation in relation_path:
        current = kg.get_neighbors(current, relation=relation)
    # 贝多芬 →(出生地)→ 波恩 →(所属国家)→ 德国 →(首都)→ 柏林
    return current
```

### 3.2 最短路径——实体关系发现

```python
def find_relationship(kg, entity_a, entity_b, max_depth=4):
    """
    发现两个实体之间的关系链:
    "乔布斯和比尔盖茨什么关系？"
    
    本质上是BFS找最短路径(限制深度)
    """
    # BFS遍历找最短关系路径
    queue = [(entity_a, [entity_a])]
    visited = {entity_a}
    
    while queue:
        current, path = queue.pop(0)
        
        if current == entity_b:
            return path  # 找到最短关系链
        
        if len(path) > max_depth:
            continue
        
        for neighbor, relation in kg.get_all_neighbors(current):
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append((neighbor, path + [(relation, neighbor)]))
    
    return None  # 在max_depth内未找到连接

# 示例输出:
# 乔布斯 →(创办)→ 苹果公司 →(竞争对手)→ 微软 →(创始人)→ 比尔盖茨
```

### 3.3 子图模式匹配——语义搜索

```python
def subgraph_pattern_matching(kg, pattern):
    """
    子图模式匹配:
    查询 "出生在纽约的诺贝尔奖获得者" =
    
    模式:
      ?person --(出生地)--> 纽约
      ?person --(获得奖项)--> ?award
      ?award  --(类型)--> 诺贝尔奖
    
    本质：在图中找所有匹配该模式的子图
    """
    results = []
    
    # 从约束最强的节点开始（纽约 → 出生地反向 → 候选人物集合）
    candidates = kg.get_neighbors("纽约", relation="出生地", reverse=True)
    
    # 对候选进行下一个约束过滤
    for person in candidates:
        awards = kg.get_neighbors(person, relation="获得奖项")
        for award in awards:
            if kg.has_edge(award, "诺贝尔奖", relation="类型"):
                results.append(person)
    
    return results
```

### 3.4 图嵌入——实体关系预测(链接预测)

```python
"""
TransE 模型: h + r ≈ t
将实体和关系都嵌入为向量，使得 head + relation ≈ tail

用于:
- 知识图谱补全(预测缺失的关系)
- 实体推荐(找到语义相似的实体)
"""

def transE_score(head_emb, relation_emb, tail_emb):
    """
    评分函数：距离越小越可能是真实三元组
    """
    return -np.linalg.norm(head_emb + relation_emb - tail_emb)

# 预测: (乔布斯, 毕业于, ?) 
# head_emb("乔布斯") + relation_emb("毕业于") ≈ tail_emb(?)
# 在所有大学实体中找距离最近的 → "里德学院"(辍学)
```

## 四、技术亮点

### 亮点 1：增量图构建——从非结构化网页到结构化知识

| 阶段 | 方法 | 输入→输出 |
|------|------|----------|
| 实体提取 | NER(命名实体识别) | 网页文本 → 实体mention |
| 实体消歧 | 图上下文+共现 | "苹果"→ Apple Inc. vs 苹果(水果) |
| 关系抽取 | 远程监督+深度学习 | 句子 → (实体A, 关系, 实体B) |
| 知识融合 | 实体对齐(图匹配) | 多源知识图谱 → 统一图 |

关键技术：利用**已有图结构**辅助新知识提取（实体消歧时看邻居关系）。

### 亮点 2：查询时间复杂度优化

| 查询类型 | 朴素方法 | 优化方法 | 加速 |
|---------|---------|---------|------|
| 单跳邻居查询 | 全图扫描 O(E) | 邻接表索引 O(度) | 10⁶x |
| 两跳路径 | O(V²) | 预计算+双向BFS | 10⁴x |
| 子图模式匹配 | NP-hard(最坏) | 查询优化+约束传播 | 实际可行 |
| 最短路径 | Dijkstra O(V logV) | 双向BFS+剪枝 | 100x |

### 亮点 3：知识推理——超越存储的事实

```
已存储事实:
  (A, 是...的父亲, B)
  (B, 是...的父亲, C)

推理得到(未显式存储):
  (A, 是...的祖父, C)    ← 路径推理
  (C, 是...的孙子, A)    ← 反向推理

实现: 规则引擎 + 图路径搜索
规则: 父亲(X,Y) ∧ 父亲(Y,Z) → 祖父(X,Z)
```

## 五、面试与项目参考

### 高频面试题

| 问题 | 参考答案要点 |
|------|-------------|
| 知识图谱本质是什么数据结构？ | 有向标记图(Labeled Directed Graph)；节点=实体，有向边=关系；存储为三元组(h,r,t) |
| 如何在知识图谱中做问答？ | 问题→实体识别+关系解析→图遍历/子图匹配→返回答案 |
| 图遍历BFS和DFS在KG中的用途？ | BFS找最短关系链(两实体怎么关联)；DFS做深度推理(多跳路径) |
| 知识图谱补全用什么方法？ | TransE/RotatE等嵌入模型：h+r≈t；本质是链接预测(图论) |
| 如何处理知识图谱的规模？ | 分布式图存储+索引+查询优化+预计算热门路径 |

### 可复用的设计模式

```
模式1: 图遍历式问答
适用场景: 任何需要基于关系回答问题的场景(FAQ、客服、搜索)
实现思路: 实体识别→关系解析→BFS/DFS遍历→剪枝→返回TopK

模式2: 路径推理
适用场景: 发现隐含关系、推荐理由生成
实现思路: 限深BFS找所有路径→路径评分→选最优解释

模式3: 子图匹配做复杂查询
适用场景: 多约束条件的组合查询(如："AI方向、985本科、3年经验的候选人")
实现思路: 条件→子图模式→约束传播+索引→匹配结果
```
