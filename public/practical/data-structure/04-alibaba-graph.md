## 二、图的存储设计

### 2.1 存储方案对比

| 存储方式 | 空间 | 遍历效率 | 适用场景 |
|----------|------|---------|---------|
| 邻接矩阵 | O(V²) | 查边O(1) | 稠密图，节点少 |
| 邻接表 | O(V+E) | 遍历邻居O(degree) | 稀疏图，动态增删 |
| CSR (压缩行存储) | O(V+E) | 遍历极快(内存连续) | 静态图，批量计算 |
| 边表 | O(E) | 遍历所有边O(E) | 边计算(Kruskal等) |

### 2.2 阿里图存储选择

```
在线服务 (实时推荐/风控):
  → 邻接表 + 分布式分片 (按顶点ID哈希分片到不同机器)
  → 为什么：支持动态添加好友/删除关系，局部遍历高效

离线分析 (社区发现/PageRank):
  → CSR格式 + 分布式图计算引擎 (阿里GraphScope)
  → 为什么：批量计算时内存连续访问，CPU缓存友好
```

### 2.3 分布式图分片策略

```
10亿节点如何分布到1000台机器？

方案A: 顶点切分 (Vertex-Cut)
  ┌──────┐  ┌──────┐  ┌──────┐
  │机器1  │  │机器2  │  │机器3  │
  │A,B,C  │  │D,E,F  │  │G,H,I  │
  └──────┘  └──────┘  └──────┘
  优点：每个顶点的邻接表完整存储在一台机器
  缺点：跨分片边需要网络通信

方案B: 边切分 (Edge-Cut)  ← 阿里采用
  热点顶点(大V)的边分散到多台机器
  优点：负载更均衡(大V不会压垮单机)
  缺点：聚合时需要 AllReduce
```

## 三、核心算法应用

### 3.1 BFS 好友推荐 (2-hop 社交扩散)

```
目标：为用户A推荐「朋友的朋友」

算法：
  1. 从A出发，BFS第1层 → 获得A的所有直接好友集合 F1
  2. BFS第2层 → 获得好友的好友集合 F2
  3. 候选集 = F2 - F1 - {A}  (去掉已是好友的人)
  4. 按「共同好友数」排序 → Top K 推荐

优化：
  - 限制BFS深度为2 (社交推荐超过3跳意义不大)
  - 邻居采样：大V的好友太多时随机采样(上限500)
  - 双向BFS：从A和候选人同时出发，相遇即有路径
```

```python
from collections import deque, Counter

def recommend_friends(graph, user, top_k=10):
    """2-hop BFS 好友推荐"""
    # 第1层：直接好友
    direct_friends = set(graph[user])
    
    # 第2层：好友的好友
    mutual_count = Counter()  # 候选人 → 共同好友数
    
    for friend in direct_friends:
        for fof in graph[friend]:  # friend of friend
            if fof != user and fof not in direct_friends:
                mutual_count[fof] += 1
    
    # 按共同好友数排序
    return mutual_count.most_common(top_k)
```

### 3.2 PageRank 商品权重计算

```
应用：淘宝搜索结果排序中的「商品权威度」

原理：
  - 商品构成图：用户购买/收藏/加购 = 一条"投票"边
  - 被越多高权重用户购买的商品，权重越高
  - 迭代公式：PR(v) = (1-d)/N + d × Σ PR(u)/Out(u)
  
工程实现：
  - BSP (Bulk Synchronous Parallel) 模型
  - 每轮迭代：各节点向邻居发送贡献值
  - 收敛条件：所有节点PR值变化 < ε
  - 通常 10-20 轮收敛
```

### 3.3 连通分量——风控团伙检测

```
算法：Union-Find (并查集)

步骤：
  1. 构建关联图 (共享设备/IP/手机号/收货地址 = 边)
  2. Union-Find 找到所有连通分量
  3. 每个连通分量 = 一个关联群体
  4. 若群体中有已标记黑产 → 整个群体标为高风险

代码示例：
```

```python
class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n
        self.size = [1] * n
    
    def find(self, x):
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])  # 路径压缩
        return self.parent[x]
    
    def union(self, x, y):
        rx, ry = self.find(x), self.find(y)
        if rx == ry:
            return
        # 按秩合并
        if self.rank[rx] < self.rank[ry]:
            rx, ry = ry, rx
        self.parent[ry] = rx
        self.size[rx] += self.size[ry]
        if self.rank[rx] == self.rank[ry]:
            self.rank[rx] += 1

# 风控示例
uf = UnionFind(1000000)  # 100万账号
# 发现共享关系
uf.union(account_a, account_b)  # 共用设备
uf.union(account_b, account_c)  # 共用IP
# account_a,b,c 现在属于同一团伙
```

### 3.4 最短路径——物流路径规划

```
应用：菜鸟物流网络中的最优配送路径

图模型：
```

## 五、图神经网络 (GNN) 在推荐中的应用

### 5.1 GraphSAGE 用于商品推荐

```
传统协同过滤的问题：
  - 只利用了直接交互(1-hop)信息
  - 冷启动商品没有交互记录

GNN的优势：
  - 聚合多跳邻居信息 → 利用图结构
  - 新商品只要有类目/属性连接 → 就能学到表征

GraphSAGE 流程：
  1. 对每个节点，采样K跳邻居
  2. 逐层聚合邻居特征 (均值/注意力/LSTM)
  3. 得到节点嵌入向量 (Embedding)
  4. 用户嵌入 · 商品嵌入 = 推荐分数
```

## 七、面试高频问题

### Q1: 图的存储方式有哪些？如何选择？

> **答题要点**：邻接矩阵O(V²)空间适合稠密图和快速查边；邻接表O(V+E)适合稀疏图和遍历邻居；CSR(压缩稀疏行)适合静态图批量计算(内存连续，缓存友好)。社交网络是典型稀疏图(E << V²)，一般用邻接表。

### Q2: BFS 和 DFS 的区别？各适合什么场景？

> **答题要点**：BFS用队列，按层遍历，适合最短路径/层级关系(好友推荐的K跳)；DFS用栈/递归，深入探索，适合路径查找/拓扑排序/连通性判断。空间上BFS是O(宽度)，DFS是O(深度)。社交推荐用BFS(按跳数)，风控路径追踪用DFS。

### Q3: 如何在十亿节点的图上做实时查询？

> **答题要点**：①图分片(顶点哈希分布到多机)；②本地性优化(社区检测后将关联紧密的节点放同机)；③缓存(热点用户的邻接表缓存在内存)；④索引(对顶点属性建倒排索引加速过滤)；⑤深度裁剪(限制BFS层数+邻居采样)。

### Q4: PageRank 算法的原理？

> **答题要点**：模拟随机游走。用户以概率d点击当前页面的链接，以概率(1-d)随机跳转。迭代计算每个页面被访问的概率。公式：PR(v) = (1-d)/N + d×Σ(PR(u)/Out(u))。通常d=0.85，迭代10-20轮收敛。工程上用BSP并行模型分布式计算。

### Q5: 并查集(Union-Find)的时间复杂度？优化手段？

> **答题要点**：朴素实现 Find O(n)。优化①路径压缩：find时将路径上所有节点直接指向根。优化②按秩合并：矮树挂高树下。两者结合后均摊复杂度O(α(n))，α是反阿克曼函数，实际≤5，可视为常数。
