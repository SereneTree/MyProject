## 通用设计原则

阅读完所有案例后，可以总结出大厂 MySQL 设计的几条**普遍规律**：

1. **业务约束优于技术兜底**：能用产品决策简化的，绝不堆技术（如 B 站强制二级评论）
2. **基因分片优于查询路由**：让分片键从业务 ID 中可解析，省去映射表
3. **DB 永远是最后一道防线**：业务约束 + 唯一键 + `字段 >= 0` 一起兜底
4. **冷热分级是必然**：核心库容量必须可控，老数据归档
5. **核心链路只做最简事**：写主库 + 发 MQ，其他系统订阅消费
6. **对账兜底最终一致性**：分布式系统不存在 100% 一致，只能定时对账
