# 阿里巴巴智能客服对话系统

## 应用场景

阿里巴巴电商生态（淘宝、天猫、1688）日均产生**数千万次**客服咨询，涵盖售前咨询（商品信息、优惠活动）、售后服务（退换货、物流查询）、投诉处理等场景。智能客服系统需要**7×24小时**即时响应，在保证回答准确性的前提下减少人工客服压力。

### 业务挑战

- **海量并发**：大促期间（双11）峰值咨询量达**数亿次/天**，人工不可能全覆盖
- **问题多样**：从"这件衣服起球吗"到"跨境退税怎么操作"，领域知识庞杂
- **精准理解**：用户表达模糊（"那个东西怎么还没到"），需要结合上下文和订单信息理解
- **情感敏感**：投诉用户情绪激动，AI 需要识别并适时转人工
- **实时更新**：促销规则、物流状态、库存信息随时变化，答案不能过时

## 设计思路

### 1. 意图识别与槽位提取

**意图体系**示例（树形结构）：

```
电商客服意图
├── 售前咨询
│   ├── 商品详情询问（材质、尺码、颜色）
│   ├── 优惠活动查询（满减、券）
│   └── 比价/推荐
├── 售后服务
│   ├── 物流查询
│   ├── 退款/退货
│   ├── 换货
│   └── 发票开具
├── 投诉
│   ├── 商品质量
│   ├── 物流延迟
│   └── 服务态度
└── 闲聊/无关
```

**槽位提取示例**：

| 用户输入 | 识别意图 | 提取槽位 |
|---------|---------|---------|
| "我上周买的红色连衣裙还没到" | 物流查询 | 商品=红色连衣裙, 时间=上周 |
| "想退那个299的包" | 退款 | 金额=299, 商品=包 |
| "这个手机支持5G不" | 商品详情 | 商品=手机, 属性=网络制式 |

### 2. 知识图谱驱动的精准回答

**电商知识图谱结构**：

```
商品实体
├── 属性：名称、价格、规格、库存、评分
├── 关系：belongs_to(店铺)、has_category(类目)
└── 动态属性：物流状态、促销信息（实时更新）

规则实体
├── 退换货规则：7天无理由、质量问题15天
├── 优惠规则：满减门槛、叠加规则
└── 物流规则：发货时效、配送范围
```

**查询过程**：
```
用户: "我3天前买的耳机能退吗？"
    ↓
意图: 退款咨询
槽位: {商品类型: 耳机, 购买时间: 3天前}
    ↓
知识图谱查询:
  - 该耳机是否支持7天无理由？→ 查商品属性
  - 3天 < 7天 → 满足退货条件
  - 退货流程 → 查规则实体
    ↓
回答: "您购买的耳机在7天无理由退货期内，可以申请退款。
      请进入 订单详情→申请退款→选择退款原因 即可..."
```

### 3. RAG 检索增强生成

对于知识图谱未覆盖的复杂问题，使用 RAG：

```
用户问题
    ↓
Query 改写 & 向量化
    ↓
向量检索（从商品详情页、FAQ文档、历史优秀回答中检索）
    ↓
Top-K 相关片段作为 Context
    ↓
LLM 基于 Context 生成回答
    ↓
答案质量校验（是否有幻觉、是否与检索内容一致）
    ↓
输出给用户
```

**RAG 的优势**：
- 避免 LLM 幻觉（hallucination）——答案有据可查
- 知识实时更新——只需更新文档库，无需重新训练模型
- 可追溯——每个回答都能关联到原始数据源

### 4. 多轮对话管理

**对话状态追踪（DST）**示例：

```
轮次1: 用户: "我想退货"
       状态: {intent: 退货, 商品: null, 原因: null}
       系统: "请问您想退哪个订单的商品？"

轮次2: 用户: "就是昨天那个"
       状态: {intent: 退货, 商品: 订单#2024xxx(昨天), 原因: null}
       系统: "好的，请问退货原因是什么？"

轮次3: 用户: "尺码不合适"
       状态: {intent: 退货, 商品: 订单#2024xxx, 原因: 尺码不合适}
       系统: "已为您提交退货申请，7天无理由退货..."
```

**关键技术**：
- **指代消解**："昨天那个" → 关联到具体订单
- **省略补全**：用户省略的信息从上下文推断
- **状态追踪**：累积多轮信息，直到收集完所有必要槽位

### 5. 情感感知与智能转人工

```
情感检测:
  正面/中性 → 继续AI服务
  负面(轻度) → 调整语气为更温和，优先解决问题
  负面(强烈) → 立即转人工 + 预警标记

触发转人工的条件:
  1. 用户连续3次表达不满
  2. 用户明确要求"转人工"
  3. AI 连续2次未能解决问题（用户重复提问）
  4. 涉及敏感话题（法律纠纷、人身安全）
```

## 技术亮点

### 亮点一：千人千面的回答风格

根据用户画像调整回答风格：
- **年轻用户**：轻松活泼，可用表情包
- **高价值客户**：正式尊重，优先处理
- **老年用户**：简洁直白，避免术语

### 亮点二：实时知识热更新

- 商品上下架、价格变动 → 秒级同步到知识图谱
- 新促销规则发布 → 5分钟内生效
- 物流状态变化 → 实时反映在回答中

### 亮点三：人机协作模式

```
完全AI服务: 处理85%的常见问题
AI辅助人工: AI预拟答案，人工一键发送/修改 → 效率提升3倍
纯人工服务: 仅处理最复杂的5%投诉/纠纷
```

### 亮点四：效果归因与AB实验

- 每个回答记录来源（知识图谱/RAG/模板/LLM）
- 用户满意度归因到具体策略
- 持续AB实验验证每次模型升级的效果

## 启发与思考

1. **结构化 + 非结构化结合**：知识图谱处理精确查询，RAG处理长尾问题，LLM兜底
2. **渐进式自动化**：不追求100%AI替代，而是找到人机协作的最佳平衡点
3. **实时性是生命线**：电商场景信息变化极快，系统必须保证知识的时效性
4. **用户体验优先**：宁可转人工也不给错误答案，信任比效率重要
