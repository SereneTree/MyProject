# 美团智能配送调度与路径规划

## 应用场景

美团外卖日均订单量超过**6000万单**，覆盖全国 2800+ 城市，活跃骑手超百万。系统需要在用户下单后**毫秒级**完成"将哪个订单分配给哪个骑手"的决策，并为骑手规划最优配送路径，确保在承诺时间内送达。

### 业务挑战

- **实时性极强**：新订单每秒涌入，骑手位置持续变化，必须实时决策
- **约束条件复杂**：时间窗（30分钟送达）、容量（一次最多带几单）、区域限制、交通状况
- **目标多元**：既要缩短用户等待时间，又要保证骑手收入公平，还要控制平台成本
- **动态不确定性**：堵车、恶劣天气、商户出餐慢、用户改地址等突发情况
- **规模巨大**：高峰期同时在途数百万订单 × 百万骑手的匹配问题

## 设计思路

### 1. ETA 预估模型（预计到达时间）

ETA 是整个调度系统的**基石**——派单和路径规划都依赖精准的时间预估。

**多因子 ETA 模型**：

```
ETA = f(距离, 路况, 天气, 时段, 商户出餐速度, 楼层/电梯, 历史数据)

输入特征:
├── 空间特征: 直线距离、路网距离、路段等级
├── 时间特征: 当前时段（午高峰）、星期几、节假日
├── 实时特征: 交通拥堵指数、天气（雨天配送慢20%）
├── 商户特征: 历史出餐时间分布（火锅店慢、快餐店快）
├── 骑手特征: 骑手熟练度、车辆类型（电动车/摩托）
└── 环境特征: 楼层（无电梯6楼 vs 有电梯20楼）、小区门禁
```

**模型架构**：Wide & Deep + 时空 Transformer

- Wide部分：捕获"某路段+高峰期"这类明确规则
- Deep部分：学习复杂非线性关系
- Transformer：建模路径序列的时序依赖

### 2. 派单决策模型

**问题建模**：这是一个**在线二部图匹配**问题。

```
订单集合 O = {o1, o2, ..., on}    ←→    骑手集合 R = {r1, r2, ..., rm}

目标: 找到匹配 M: O → R，使得全局代价最小

代价函数 = α × 用户等待时间 + β × 骑手绕路距离 + γ × 超时风险
```

**传统方法 vs AI方法**：

| 方法 | 思路 | 局限 |
|------|------|------|
| 贪心 | 每单找最近骑手 | 局部最优≠全局最优 |
| 匈牙利算法 | 全局最优匹配 | 无法处理动态到达的新订单 |
| **强化学习** | 考虑未来订单，做延迟决策 | ✅ 美团实际采用 |

**RL 建模**：

```
状态 s: 当前所有待分配订单 + 所有骑手状态
动作 a: 将订单 oi 分配给骑手 rj（或等待）
奖励 r: -超时惩罚 - 绕路成本 + 按时送达奖励
策略 π: 学习"何时派、派给谁"的最优策略
```

**关键创新——"等待"决策**：

系统学会了"暂时不派"的策略：
- 预判 3 分钟后会有顺路订单产生 → 等一等再一起派
- 类比：坐电梯等人，多等 10 秒可能多载 3 人，整体效率更高

### 3. 路径规划模型

骑手手上通常有**3-8单**，需要规划最优取/送顺序和路线。

**问题本质**：带时间窗的旅行商问题（TSPTW）—— NP-hard。

```
骑手当前有4个任务:
  - 取餐A（商户1）→ 送餐A（用户a, deadline 12:30）
  - 取餐B（商户2）→ 送餐B（用户b, deadline 12:25）

约束:
  - 必须先取后送（取A在送A之前）
  - 时间窗约束（deadline前送达）
  - 路网约束（单行道、禁行区域）

目标: 最小化总路程，同时满足所有deadline
```

**求解方法**：

```
┌─────────────────────────────────────────────┐
│ 1. 构造初始解: 最近邻启发式（贪心）              │
│    当前位置 → 最近的未完成任务 → 下一个...      │
├─────────────────────────────────────────────┤
│ 2. 局部搜索优化: 2-opt / Or-opt 邻域搜索       │
│    交换/移动任务顺序，检查是否改善               │
├─────────────────────────────────────────────┤
│ 3. 深度学习加速: Attention Model (AM)          │
│    用 Transformer 编码任务序列                  │
│    Decoder 自回归输出访问顺序                   │
│    训练: REINFORCE 策略梯度                    │
└─────────────────────────────────────────────┘
```

### 4. 动态重调度

现实中充满不确定性，系统必须持续"重新规划"：

| 触发事件 | 系统响应 |
|---------|---------|
| 商户出餐延迟 | 重新评估该骑手后续订单的deadline风险 |
| 骑手接到新单 | 重新规划路径，插入新任务 |
| 交通突发拥堵 | 更新ETA，可能触发订单转移 |
| 用户取消订单 | 释放骑手容量，重新接单 |
| 超时预警 | 启动"抢救"机制：转单/加急 |

## 技术亮点

### 亮点一：全局视角的强化学习调度

- 不是"来一单派一单"的贪心，而是**考虑未来5分钟的订单分布**做决策
- 通过历史数据学习"热区预判"：午高峰某区域即将涌入大量订单 → 提前调度骑手前往
- 实际效果：比贪心策略减少 15% 的骑手绕路，降低 8% 超时率

### 亮点二：分钟级 ETA 更新

- 每 60 秒更新一次全城路网通行时间
- 融合 GPS 轨迹、交通信号灯、天气预报
- 预测精度：MAE < 3分钟（平均误差不到3分钟）

### 亮点三：多智能体协同

- 单骑手决策不能脱离全局——一个骑手接了"顺路单"，可能导致另一骑手无单可接
- 系统建模为**多智能体协作问题**：每个骑手是一个 Agent，通过中心化训练 + 分布式执行
- 目标：纳什均衡点——没有任何骑手能通过单方面改变策略获益

### 亮点四：公平性约束

- 避免"忙的忙死，闲的闲死"：引入骑手负载均衡约束
- 新手骑手保护：前100单给予更宽松的时间窗
- 高峰补贴机制：RL 奖励函数中加入公平性项

## 启发与思考

1. **AI 课上的理论真的在用**：A*搜索、CSP、MDP、RL 全部有直接对应的大规模工业应用
2. **组合优化 + 学习**：传统运筹学方法 + 深度学习 = 更强的泛化能力和实时性
3. **实时性是最大挑战**：秒级决策 + 分钟级更新 + 动态重规划，这比课程作业复杂得多
4. **多目标平衡**：现实中没有单一目标，必须在效率、公平、成本之间找平衡
