# 第3章 算法复杂度与问题难度

> **考试优先级：中高** ——本章是算法分析的理论基础。大 O 记号和 P/NP 类是必考概念。习题集第 26、27 题直接考查。

## 核心知识速览

| 概念 | 一句话含义 | 考试权重 |
|------|-----------|---------|
| 运行时间 `T(n)` | 算法在所有规模为 n 的输入上的最坏步数 | ⭐⭐⭐ |
| 大 O 记号 `O(g(n))` | 渐近上界：存在常数使 f(n) ≤ c·g(n) | ⭐⭐⭐ |
| 多项式时间算法 | 运行时间为 `O(nᵏ)` 的算法 | ⭐⭐⭐ |
| 复杂度类 P | 可以多项式时间**求解**的判定问题集合 | ⭐⭐⭐ |
| 复杂度类 NP | 解可以多项式时间**验证**的判定问题集合 | ⭐⭐⭐ |
| NP-难（NP-hard） | 至少和 NP 中最难问题一样难 | ⭐⭐ |
| NP-完全（NP-complete） | 既在 NP 中，又是 NP-难的 | ⭐⭐⭐ |
| Co-NP | "否"的答案可以多项式时间验证的问题 | ⭐ |

## 1. 运行时间

### 直觉
不同计算机的运行速度不同，但我们更关心算法随问题规模增大时的**增长趋势**，而不是精确的运行秒数。

> **定义 3.1（运行时间）：** 算法的**运行时间** `T(n)` 是在所有规模为 `n` 的输入中，算法所需**基本操作数的最大值**（最坏情况）。

**输入规模的度量：**
- 图的输入用邻接矩阵或关联矩阵表示，所需位数是顶点数和边数的线性函数
- 包含数值的网络问题，输入规模还随数值大小对数增长

---

## 2. 大 O 记号（渐近上界）

### 直觉
忽略常数因子和低阶项，只关注主导增长趋势。

> **定义 3.2（渐近上界）：** `f(n)` 是 `O(g(n))`，若存在常数 `c > 0` 和 `n₀ ≥ 0`，使得对所有 `n ≥ n₀`，有 `f(n) ≤ c · g(n)`。

### 直觉理解
- "对足够大的 n，`f(n)` 最多是 `g(n)` 的常数倍"
- 目标是找最小（增长最慢）的 `g`

### 常见函数增长速度比较

$$O(1) \subset O(\log n) \subset O(n) \subset O(n\log n) \subset O(n^2) \subset O(n^3) \subset O(2^n) \subset O(n!)$$

### 举例

> **例 3.3：** `f(n) = 4n³ + 6n² + 3n + 4`
> 对 n ≥ 1，有 `1 ≤ n ≤ n² ≤ n³`，故：
> `f(n) ≤ 4n³ + 6n³ + 3n³ + 4n³ = 17n³`
> 取 `g(n) = n³`，`c = 17`，`n₀ = 1`，故 `f(n) = O(n³)` ✓

### 算法复杂度典型例子

| 算法 | 复杂度 |
|------|-------|
| Gauss 消去法（n×n 矩阵） | `O(n³)` |
| Prüfer 编码（n 顶点树） | `O(n²)`（可优化至 `O(n)`） |
| BFS / DFS | `O(\|V\| · \|E\|)`，优化后 `O(\|V\| + \|E\|)` |
| Prim / Dijkstra（基本版） | `O(\|V\| · \|E\|)`，优化后 `O(\|V\|²)` |
| Kruskal（含排序） | `O(\|E\| log \|E\|)` |
| Bellman-Ford | `O(\|V\|³)`，优化后 `O(\|V\| · \|A\|)` |

**运行时间对比表（假设每秒执行 10⁶ 次基本操作）：**

| n | n | n² | n³ | 2ⁿ |
|---|---|----|----|-----|
| 10 | <1秒 | <1秒 | <1秒 | <1秒 |
| 30 | <1秒 | <1秒 | <1秒 | 约18分钟 |
| 50 | <1秒 | <1秒 | <1秒 | 约36年 |
| 10³ | <1秒 | 1秒 | 约18分钟 | 无法计算 |
| 10⁶ | 1秒 | 约12天 | 约31710年 | 无法计算 |

> 🎯 **考点：** 习题集第 26 题直接考查大 O 性质的证明，包括：`f+g = O(max{f,g})`、O 的传递性、以及证明 `2^(2n)` 不是 `O(2ⁿ)`。

## 3. 多项式时间算法

> **定义 3.6（多项式时间算法）：** 若算法运行时间 `T(n) = O(nᵏ)`（k 为某个常数），称为**多项式时间算法**。

**为什么多项式时间是"高效"的分界线？**
- 实践中，存在多项式时间算法往往意味着存在**低次**多项式时间算法
- 不存在多项式算法的问题在实践中往往真的很难
- 多项式时间算法可以合理扩展到大规模输入；指数时间算法不能

---

## 4. 复杂度类 P 与 NP

### P 类（多项式时间可解）

> **定义 3.7：** **复杂度类 P** 是所有存在多项式时间算法的（判定）问题的集合。

**P 中的例子：**
- 用 Gauss 消去法求矩阵的秩
- 用欧几里得算法求最大公约数（GCD）
- 在图中找最大匹配（二部图）
- 归并排序

### NP 类（多项式时间可验证）

> **定义 3.8：** **复杂度类 NP**（非确定性多项式）是所有"给定一个候选解，可在多项式时间内**验证**其正确性"的问题集合。

**关键区分：**
- **P**：找到解很快（多项式时间）
- **NP**：验证给定解很快，但找解可能很慢

**NP 中的例子：**

> **例 3.9（背包问题）：** 给定 n 个物品（各有重量 `wᵢ` 和价值 `vᵢ`）和容量 `W`，选取物品使总重 ≤ W 且总价值最大。
> - 找最优解：困难（指数时间）
> - 验证给定方案是否合法：容易（只需求和比较）

> 🎯 **重要猜想：P ≠ NP**（即找到解确实比验证解更难）。这是数学界 Clay 千禧年大奖问题之一，奖金 100 万美元，至今未被证明。

---

## 5. NP-难与 NP-完全

> **定义 3.10（NP-难）：** 若 NP 中的每个问题都可在多项式时间内**归约**到问题 A，则 A 是 **NP-难（NP-hard）**的。

- NP-难问题**不一定**在 NP 中（甚至可能更难）
- 若 P ≠ NP，NP-难问题不存在多项式时间算法

> **定义 3.14（NP-完全）：** 既在 NP 中，又是 NP-难的问题称为 **NP-完全（NP-complete）**。

**NP-完全问题例子：**

> **例 3.11（旅行商问题，TSP）：** 给定 n 个城市及城市间距离，找访问每个城市恰好一次并返回起点的最短路线。

**复杂度关系图：**

```
┌─────────────────────────────────────┐
│            NP-难 (NP-hard)          │
│  ┌──────────────────────────────┐  │
│  │      NP                      │  │
│  │  ┌───────────────────────┐  │  │
│  │  │  NP-完全 (NP-complete) │  │  │
│  │  └───────────────────────┘  │  │
│  │  ┌──────────────────┐       │  │
│  │  │        P          │       │  │
│  │  └──────────────────┘       │  │
│  └──────────────────────────────┘  │
└─────────────────────────────────────┘
```

> 🎯 **考点：** 必须能区分 P、NP、NP-难、NP-完全四个概念，并能举出每类的例子。"图中找最短路径 = P"，"TSP = NP-完全"是标准例子。

---

## 6. Co-NP

> **定义 3.12（Co-NP）：** 若问题 X 的**否定答案**可在多项式时间内验证，则 X ∈ Co-NP。

- 若 X ∈ NP，则其补问题 X' ∈ Co-NP
- 例：素数判定 ∈ Co-NP（若 n 是合数，可给出因子 d 来验证）

## 常见错误

- **O 记号的方向**：`f = O(g)` 意味着 f 被 g 从上方界定（f ≤ cg），不是 f ≥ cg。
- **NP 不等于"困难"**：NP 是"解可验证"，不是"一定很难"；P ⊆ NP。
- **NP-难 ≠ NP-完全**：NP-完全必须既是 NP-难，又在 NP 中。
- **多项式时间的意义**：`O(n¹⁰⁰)` 也是多项式时间，但实际上未必"高效"；不过区分 P 和非 P 在实践中确实有效。
- **欧几里得算法的输入规模**：输入规模是 `log a + log b`（二进制位数），不是 `a + b`。
