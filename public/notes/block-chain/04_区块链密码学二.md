## 4.1 古典密码学

### 凯撒密码（Caesar Cipher）
- 最早期的移位密码，密钥 K=3（字母向后移 3 位）
- 安全性依赖于**算法保密**（受限算法 Restricted Algorithm）
- 缺陷：算法一旦泄露即完全失效，更新算法成本极高

### 两大基础技术

| 技术 | 说明 | 示例 |
|------|------|------|
| **替换密码**（Substitution）| 用替换表将明文字母逐一替换 | "dog" → "eph" |
| **置换密码**（Permutation）| 保持字母不变，打乱位置和顺序 | "dog" → "ogd" |

### 单表替换密码
- 每个明文字母对应固定的密文字母
- 缺陷：密文中单字母频率分布与明文相同，**无法抵抗统计分析**

### 多表替换密码
- 同一明文字母对应不同密文字母（多个映射函数）
- 隐藏单字母频率分布，安全性更高
- 示例：维吉尼亚密码（使用密钥 "creny"，按密钥字母在字母表中的位置排列顺序加密）

### 古典密码分类

```
古典密码
├── 移位密码（凯撒密码）
├── 替换密码
│   ├── 单表替换
│   └── 多表替换
└── 置换密码
```

## 4.2 现代密码学基础

### 香农（Claude Shannon）的贡献
- 1949 年发表《保密系统的通信理论》
- 奠定了现代密码学的信息论基础
- 提出两大安全设计原则：**混淆**（Confusion）与**扩散**（Diffusion）

### 分组密码（Block Cipher）
- 思想：将明文数值序列按长度 n 分组，每组在密钥 k 控制下转换为等长密文
- 两大安全原则：
  - **混淆**（Substitution）：使密文与明文的关系复杂，隐藏明文统计规律
  - **扩散**（Permutation/Diffusion）：使明文每一位影响尽可能多的密文位，分散冗余信息

## 4.3 公钥密码体制

### 设计动机
- 解决对称密码中的**密钥管理和分发**难题
- 基于**数学函数**而非替换/置换
- 使用两把密钥：**公钥**（公开）和**私钥**（保密）

### 工作原理
```
加密过程：
  发送方用接收方公钥加密消息 → 发送密文

解密过程：
  接收方用自己私钥解密密文 → 得到明文

关键：公钥无法推导出私钥
```

## 4.4 RSA 公钥密码算法

### 背景
- 1978 年，MIT 的 Rivest、Shamir、Adleman 提出
- 第一个成熟的公钥密码体制
- 2002 年三人获图灵奖

### 安全性基础
> 安全性依赖于**大整数分解难题**：对于大素数乘积 n = p × q，目前无多项式时间算法分解出 p 和 q。

### 关键参数

| 参数 | 说明 |
|------|------|
| n = p × q | 公开，p、q 为大素数且 p ≠ q |
| e | 公钥指数，公开 |
| d | 私钥指数，满足 `ed mod φ(n) = 1` |
| φ(n) = (p-1)(q-1) | 欧拉函数，用于计算 d |

- 已知公钥 `<n, e>`，无法推导私钥 `d`（需要知道 φ(n)，而 φ(n) 需要分解 n）

## 4.5 数字签名（Digital Signature）

### 传统签名的问题
- 手写签名便于核实，但在网络环境中无法直接使用
- 问题示例：Alice 通过网络发送转账指令，Bob 无法确认：
  1. 消息是否真的是 Alice 发的？
  2. Alice 事后是否会否认这笔转账？

### 数字签名的定义
> 一种电子标记，实现与手写签名类似的效果，保证消息真实性与不可抵赖性。

### 核心性质

| 性质 | 说明 |
|------|------|
| **不可伪造** | 除合法签名人外无法伪造 |
| **不可抵赖** | 签名人不能事后否认 |
| **可信验证** | 任何人均可用公钥验证签名有效性 |

### 数字签名 vs 手写签名

| 维度 | 数字签名 | 手写签名 |
|------|---------|---------|
| 与消息的关系 | 分离，需绑定方法 | 视为消息的一部分 |
| 验证方式 | 任何人可用公钥验证 | 需专家比对 |

### 数字签名方案的四个流程
1. **系统初始化**：生成全局系统参数
2. **密钥对生成**：生成私钥（签名密钥）和公钥（验证密钥）
3. **签名过程**：使用私钥对消息（的哈希值）签名
4. **验证过程**：使用公钥验证签名

### 为什么签名哈希值而不是直接签名消息？
> 无论消息多长，签名长度只与哈希值长度相关，计算高效且安全。

## 4.6 RSA 数字签名算法

### 工作流程

```
签名：
  1. 计算消息 M 的哈希值 h(M)
  2. 用私钥 d 对 h(M) 签名：S = h(M)^d mod n

验证：
  1. 用公钥 e 解密签名：h' = S^e mod n
  2. 自行计算 h(M)
  3. 若 h' = h(M)，则签名有效
```

## 4.7 椭圆曲线密码学（ECC）

### 为什么需要 ECC？
- RSA 需要 1024 位以上密钥才安全，存储和计算开销大
- ECC 仅需 **160 位**密钥即可达到相同安全级别

### 椭圆曲线的定义

有限域 Fp 上的椭圆曲线：

```
y² = x³ + ax + b  （以及无穷远点 O）
```

### 椭圆曲线上的加法运算

| 情形 | 定义 |
|------|------|
| P ≠ Q | R = P + Q（过 P、Q 的直线与曲线的第三个交点关于 x 轴对称点）|
| P = Q | R = 2P（切线法，即点乘运算）|
| P、Q 关于 x 轴对称 | P + Q = O（无穷远点）|

**群结构**：椭圆曲线上的点在加法运算下构成一个群，零元为无穷远点 O。

### ECC 的安全性基础
> 基于**椭圆曲线离散对数问题（ECDLP）**：已知基点 G 和 Q = kG，难以求出整数 k。
> 目前最优算法需指数级时间复杂度。

## 4.8 ECDSA 椭圆曲线数字签名算法

### 特点
- 采用素数域 Zp 上的椭圆曲线
- 是目前区块链（比特币、以太坊）最广泛使用的签名算法

### 密钥生成
1. 所有参与方共享全局域参数（选定椭圆曲线上的基点 G）
2. 签名者生成随机数 d 作为**私钥**
3. 计算 Q = d × G 作为**公钥**

### 签名生成（简化）
1. 对消息 m 计算哈希值 e = H(m)
2. 选取随机数 k，计算 R = k × G，取 r = R 的 x 坐标
3. 计算 s = k⁻¹(e + d·r) mod n
4. 签名为 (r, s)

### 签名验证
1. 计算 e = H(m)
2. 用公钥 Q 和签名 (r, s) 计算恢复点
3. 若计算结果的 x 坐标等于 r，则签名有效

## 重点总结

- **古典密码**：替换 + 置换，安全性基于算法保密，易破解
- **分组密码**：混淆 + 扩散两原则
- **RSA**：非对称加密，安全性基于大整数分解
- **ECC**：安全性基于椭圆曲线离散对数，密钥短、效率高
- **数字签名三步**：哈希 → 私钥签名 → 公钥验证
- **ECDSA**：区块链中主流数字签名算法，比特币、以太坊均使用
- 签名哈希而非原始消息：效率高，与消息长度无关

| 算法 | 安全基础 | 密钥长度 | 区块链应用 |
|------|---------|---------|----------|
| RSA | 大整数分解 | 1024+ 位 | 较少使用 |
| ECC/ECDSA | 椭圆曲线离散对数 | 160-256 位 | 比特币、以太坊 |
