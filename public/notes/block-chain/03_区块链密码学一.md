## 3.1 哈希函数（Hash Function）

### 基本定义

> 哈希函数（散列函数）：将**任意长度**的输入通过哈希算法转换为**固定长度**的输出，该输出称为**哈希值**（Hash Value）。

**通俗理解**：像一个"积木工厂"——输入任意大小的积木（原始数据），产出固定大小的积木成品（哈希值）。

### 核心特性

| 特性 | 说明 |
|------|------|
| **确定性** | 相同输入始终产生相同输出 |
| **单向性** | 无法从哈希值逆推原始输入 |
| **雪崩效应** | 输入微小变化导致输出完全不同 |
| **抗碰撞性**（Collision Free）| 难以找到两个不同输入产生相同哈希值 |
| **固定长度输出** | 无论输入多长，输出长度固定 |

### 哈希函数的应用

1. **完整性验证**：下载软件时比对官网提供的 SHA256 哈希值，确认文件未被篡改
2. **数字签名**：用私钥对合同的哈希值加密生成签名，对方用公钥验证

---

### 常见哈希算法

#### MD 系列
- MD4、MD5：输出 128 位（32 个十六进制字符），已不安全

#### SHA 系列（美国 NIST + NSA 设计）

| 算法 | 输出长度 |
|------|---------|
| SHA-1 | 160 位（40 个十六进制字符） |
| SHA-224 | 224 位 |
| **SHA-256** | **256 位（64 个十六进制字符）**，比特币使用 |
| SHA-384 | 384 位 |
| SHA-512 | 512 位 |

#### SHA-256 计算流程（简化 8 步）
1. **数据填充**：补成 512 位倍数，附加长度信息
2. **初始化**：准备 8 个标准初始常数作为种子
3. **分块处理**：按 512 位为单位分割数据块
4. **消息扩展**：扩展为 64 个 32 位"消息字"
5. 轮函数压缩（64 轮）
6. 中间哈希值累加
7. 循环处理所有数据块
8. 输出最终 256 位哈希值

#### 国密算法 SM3
- 我国自主设计的哈希算法
- 基于 SHA-256 改进，采用 Merkle-Damgard 结构
- 输入按 **512 位**分组，输出 **256 位**
- 应用：商用数字签名、消息认证码、随机数生成

## 3.2 区块的基本概念

### 区块数据结构

| 字段 | 说明 |
|------|------|
| 区块大小 | 当前区块的大小 |
| **区块头** | 前一区块哈希值、Merkle 根、时间戳、难度目标、Nonce |
| 交易计数器 | 本区块包含的交易数量 |
| 交易列表 | 具体交易内容 |

### 交易结构
- **交易输入**（Transaction Input）：指示资金来源（UTXO）
- **交易输出**（Transaction Output）：指示资金去向

### 交易池
- 所有交易在交易池中进行校验、打包
- 合法交易 → `mempool`（等待打包）
- 依赖未知交易 → `orphantx`（暂时无法上链）

## 3.3 默克尔树（Merkle Tree）

### 数据结构
- 提出者：美国计算机学家 **Ralph Merkle**（1979 年）
- 本质：**哈希二叉树**
- 结构：根节点（Root）+ 中间节点 + 叶节点（Leaf）

```
根节点（Root Hash）
├── 中间节点（两个子节点内容的哈希）
│   ├── 叶节点（数据内容或数据的哈希值）
│   └── 叶节点
└── 中间节点
    ├── 叶节点
    └── 叶节点
```

### 构建过程（自底向上）

1. 对每个数据块分别计算哈希值，得到叶节点
2. 相邻两个哈希块拼接后再哈希，得到父节点
3. 重复第 2 步，直到生成根节点（Merkle Root）
4. 若叶节点为奇数，最后一个节点与自身拼接

### 主要应用
- **完整性验证**：通过 Merkle 路径验证某笔交易是否包含在区块中
- **SPV（简单支付验证）**：轻节点无需下载完整区块链，只需 Merkle 路径即可验证交易

### 延伸：Merklix 树
- 在 Merkle 树基础上，使用**键**（如哈希值共同前缀）确定元素位置
- 支持高效插入与删除，时间复杂度为 O(ln N)
- 可提供"Merklix 证明"验证元素的存在性

## 3.4 非对称加密（Asymmetric Cryptography）

### 对比对称加密

| 类型 | 密钥 | 优点 | 缺点 |
|------|------|------|------|
| 对称加密 | 加解密使用同一密钥 | 速度快 | 密钥分发困难 |
| **非对称加密** | 公钥（Public Key）+ 私钥（Private Key）| 解决密钥分发问题 | 速度较慢 |

### 公钥密码体制工作流程

```
Alice 生成密钥对：公钥（公开）+ 私钥（保密）

Bob 发消息给 Alice：
  Bob 用 Alice 的公钥加密 → 发送密文

Alice 收到密文：
  Alice 用自己的私钥解密 → 得到明文
```

> 只有 Alice 的私钥才能解密，保证通信保密性。

### RSA 公钥算法

- 发明者：Rivest、Shamir、Adleman（MIT，1978）
- 安全性基于**大整数分解**的数学难题（目前无多项式时间算法）
- 三人于 2002 年获图灵奖

**关键参数**：
- 公钥：`<n, e>`
- 私钥：`d`（满足 `ed mod φ(n) = 1`）
- 安全性依赖：已知 n 无法高效分解出 p、q

### ECC 椭圆曲线加密

- RSA 需要 1024 位密钥，ECC 仅需 **160 位**即可达到同等安全级别
- 安全性基于**椭圆曲线离散对数问题**（ECDLP）
- 密钥更短，存储和计算开销更小
- 比特币、以太坊均使用 ECC（secp256k1 曲线）

## 3.5 数字签名

### 定义

> 数字签名是保证数据真实性和完整性的加密机制，具有高度**抗抵赖性**。

### 三个基本流程

```
1. 散列（Hash）：对消息计算哈希值
2. 签名（Sign）：用私钥对哈希值加密 → 签名
3. 验证（Verify）：用公钥解密签名得到哈希 A，再对消息计算哈希 B，A=B 则验证通过
```

### 数字签名的性质

| 性质 | 说明 |
|------|------|
| **不可伪造** | 除合法签名人外，他人难以伪造签名 |
| **不可抵赖** | 签名人不能否认自己的签名 |
| **可信验证** | 任何人均可验证签名有效性 |

### ECDSA 算法（椭圆曲线数字签名）
- 采用素数域 Zp 上的椭圆曲线
- 签名者用私钥和基点计算公钥
- 生成签名：利用随机数 k 和消息哈希值
- 验证签名：用公钥重新计算并比对

---

## 3.6 数字证书与 PKI 体系

### 数字证书的构成
- 证书持有人的公钥
- 持有人身份信息
- 证书颁发机构（CA）的签名
- 有效期

### 信任链（Trust Chain）
> CA 对证书签名 → 根 CA 对中间 CA 签名 → 层层传递信任

### PKI（Public Key Infrastructure，公开密钥基础设施）
- 基于公钥机制建立的基础设施
- 提供证书的**生成、发布、撤销**全套管理框架

## 3.7 其他加密技术（扩展）

| 技术 | 用途 |
|------|------|
| 零知识证明（ZKP）| 在不泄露数据内容的前提下证明数据满足某条件 |
| 同态加密 | 对密文直接进行计算，结果解密后与明文计算结果一致 |
| 环签名 | 匿名签名，无法确定签名者身份 |
| 盲签名 | 签名者对内容不知情，保护消息内容 |

## 重点总结

- **哈希函数**：单向、抗碰撞、雪崩效应，是区块链防篡改的基础
- **SHA-256**：比特币使用，输出 256 位；**SM3**：中国国密标准
- **默克尔树**：哈希二叉树，用于高效验证交易完整性
- **非对称加密**：公钥加密、私钥解密；私钥签名、公钥验证
- **RSA**：基于大整数分解；**ECC**：基于椭圆曲线离散对数，密钥更短
- **ECDSA**：区块链中最常用的数字签名算法
