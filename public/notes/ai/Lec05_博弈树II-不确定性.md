# 第五讲：博弈树II——不确定性

## 一、从最坏情况到平均情况

- Minimax假设对手总是选择对你最不利的行动（**最坏情况**）
- 但现实中对手可能不是完美的（**平均情况**）
- 引入**机会节点（Chance Nodes）**：结果由概率控制，而非对手

---

## 二、Expectimax搜索

### 为什么需要Expectimax？
- 明确的随机性：掷骰子
- 不可预测的对手：幽灵随机移动
- 行动可能失败：机器人移动时轮子可能打滑

### Expectimax结构
- **MAX节点**：同minimax，取最大值
- **机会节点**：计算子节点的**期望效用**
  - 加权平均（期望值）而非最小值

### Expectimax伪代码

```
value(state):
  若终止状态 → 返回效用
  若下一个为MAX → 返回 max-value(state)
  若下一个为EXP → 返回 exp-value(state)

exp-value(state):
  v = 0
  对每个后继:
    p = probability(successor)
    v += p * value(successor)
  返回 v

max-value(state):
  v = -∞
  对每个后继: v = max(v, value(successor))
  返回 v
```

### 计算示例
```
v = (1/2)(8) + (1/3)(24) + (1/6)(-12) = 4 + 8 - 2 = 10
```

### Expectimax能否剪枝？
- **不能简单剪枝**！因为概率节点的所有子节点都可能影响期望值
- 与Minimax不同，没有明确的"足够好/坏"阈值可以剪掉

## 三、概率基础复习

### 随机变量与概率分布
- 随机变量：结果未知的事件
- 概率分布：对结果赋予权重
- 基本规则：
  - 概率非负
  - 所有可能结果的概率之和为1
  - 获得更多证据时概率可能改变（条件概率）

### 期望值
- 随机变量函数的期望 = 按概率分布的加权平均
- 例：到机场的时间期望

---

## 四、概率模型与假设

### 概率从何而来？
- 简单均匀分布（掷骰子）
- 复杂模型需要大量计算
- 对手行动的概率可能来自模拟

### 模型假设与现实的匹配

| 现实 | 使用Minimax | 使用Expectimax |
|------|-------------|----------------|
| 对抗幽灵 | 赢5/5，均分483 | 赢1/5，均分-303 |
| 随机幽灵 | 赢5/5，均分493 | 赢5/5，均分503 |

- **危险乐观**：假设随机而实际对抗 → 惨败
- **危险悲观**：假设对抗而实际随机 → 错失机会
- 模型与现实的**匹配**至关重要

## 五、混合类型博弈

### Expectiminimax
- 适用于如西洋双陆棋（Backgammon）
- 环境作为额外的"随机智能体"玩家
- 每个节点计算其子节点的适当组合

### 西洋双陆棋
- 两个骰子21种可能的掷法 × ~20种合法走法
- 深度2 = 20 × (21×20)^3 ≈ 1.2×10^9
- TD-Gammon：深度2搜索 + 优秀评估函数 + RL = 世界冠军水平

### 多智能体效用
- 非零和博弈：终端有效用元组
- 每个玩家最大化自己的分量
- 可动态产生合作与竞争

## 六、蒙特卡洛树搜索（MCTS）

### 核心思想
1. **Rollout评估**：通过随机行动模拟多局游戏，统计胜负
2. **选择性搜索**：探索有助于改善根节点决策的部分

### MCTS算法四步循环

| 步骤 | 描述 |
|------|------|
| 选择(Selection) | 递归应用UCB选择路径到叶节点 |
| 扩展(Expansion) | 为叶节点添加一个子节点 |
| 模拟(Simulation) | 从新子节点运行rollout |
| 回溯(Backpropagation) | 从子节点到根更新U和N计数 |

### UCB1公式

$$UCB1(n) = \frac{U(n)}{N(n)} + C \times \sqrt{\frac{\log N(\text{Parent}(n))}{N(n)}}$$

| 项 | 含义 |
|----|------|
| U(n)/N(n) | 胜率（利用/Exploitation） |
| C × √(log N(parent)/N(n)) | 探索奖励（探索/Exploration） |
| C | 权衡参数 |

- N(n) = 节点n的rollout次数
- U(n) = 对手玩家获胜次数
- 高胜率 → 更多利用；少访问 → 更多探索

### MCTS总结

| 优势 | 说明 |
|------|------|
| 时间复杂度 | 独立于b和m |
| 通用性 | 不需要设计评估函数 |
| 渐近最优 | 当N→∞时选择minimax行动 |
| 可改进 | 可结合机器学习（如AlphaGo） |

### AlphaGo
- MCTS + 神经网络
- Rollout策略由RL和人类专家走法训练
- 结合rollout结果和训练的价值函数
