## 一、应用层概述

**应用层（Application Layer）**：TCP/IP 最高层，直接为用户提供网络服务。

- 应用架构（Application Architecture）由**应用开发者**设计，决定应用程序如何分布在终端系统上。
- 应用架构与网络架构（Internet Architecture）**不同**：网络架构是固定的，提供特定的服务集合。

---

## 二、应用架构类型

### 2.1 客户端-服务器架构（Client-Server Architecture）

| 特征 | 说明 |
|------|------|
| 服务器（Server） | 始终在线，具有**固定 IP 地址**，处理客户端请求 |
| 客户端（Client） | 向服务器发起请求，客户端之间**不直接通信** |
| 典型应用 | Web、电子邮件（Email） |
| 扩展方式 | 使用**数据中心（Data Centre）**，包含数千台服务器（如 Google、Amazon、Twitter） |

**工作流程**：客户端 → 发送请求 → 服务器（固定 IP）→ 返回响应

### 2.2 对等架构（Peer-to-Peer / P2P Architecture）

| 特征 | 说明 |
|------|------|
| 结构 | 对等节点（Peers）之间**直接通信**，无需专用服务器 |
| 节点 | 用户控制的台式机和笔记本电脑 |
| 优点 | 极强的可扩展性（每个节点既是客户端又是服务器） |
| 典型应用 | BitTorrent（文件共享） |
| 特点 | 最小化（或无）对服务器的依赖 |

### 2.3 两种架构对比

| 对比项 | 客户端-服务器 | P2P |
|--------|--------------|-----|
| 服务器 | 专用，始终在线 | 无专用服务器 |
| IP 地址 | 服务器 IP 固定 | 对等节点 IP 动态 |
| 扩展性 | 有限（受服务器性能限制） | 强（自扩展） |
| 可靠性 | 服务器是单点故障 | 去中心化，更可靠 |
| 代表 | Web、Email | BitTorrent |

## 三、进程通信（Process Communication）

**进程（Process）**：运行在终端系统上的程序实例。

- 同一主机上的进程通信：通过**操作系统**定义的进程间通信机制
- 不同主机上的进程通信：通过**网络消息**（通信双方都必须遵守协议）

### 客户端进程 vs 服务器进程

| 类型 | 定义 |
|------|------|
| **客户端进程（Client Process）** | 发起通信的一方 |
| **服务器进程（Server Process）** | 等待被联系的一方 |

> P2P 应用中，一个对等节点可以**同时担任**客户端进程和服务器进程。

### 套接字（Socket）

**套接字（Socket）**：进程与网络之间的接口，是进程发送/接收消息的"门"。

```
进程 A（主机 1）                    进程 B（主机 2）
   ↓ 写入消息                          ↑ 读取消息
[Socket - 套接字]  ← 互联网 → [Socket - 套接字]
   ↓ 由 TCP 负责传输                   ↑
```

- 消息一旦进入 socket，就由 TCP 负责传输，应用层不再控制。
- **TCP Socket** 由四元组标识：**（源 IP、源端口、目的 IP、目的端口）**

## 四、HTTP 协议（HyperText Transfer Protocol）

### 4.1 HTTP 基础

- **HTTP** 是 Web 应用的核心应用层协议。
- HTTP 定义了**消息的结构**以及客户端和服务器**如何交换消息**。
- 运行在传输层 **TCP** 之上，默认端口 **80**。

**HTTP 工作流程**：
1. 用户点击超链接 → 浏览器向服务器发送 **HTTP 请求（Request）**
2. 服务器接收请求 → 返回 **HTTP 响应（Response）**（包含请求的对象）

### 4.2 HTTP 的特性

| 特性 | 说明 |
|------|------|
| **无状态（Stateless）** | 服务器不保存客户端的请求历史信息 |
| **基于 TCP** | 先建立 TCP 连接，再传输 HTTP 消息 |
| **请求-响应模式** | 客户端发请求，服务器返回响应 |

### 4.3 HTTP 消息格式

**HTTP 请求消息（Request）**：
```
GET /somedir/page.html HTTP/1.1
Host: www.someschool.edu
User-agent: Mozilla/4.0
Connection: close
[空行]
```

**HTTP 响应消息（Response）**：
```
HTTP/1.1 200 OK
Content-type: text/html
Content-length: 6821
[空行]
[HTML 数据]
```

## 五、应用层协议的核心内容

一个**应用层协议**定义了以下内容：
- **消息类型（Type）**：如请求消息、响应消息
- **消息语法（Syntax）**：消息中的字段及字段描述
- **消息语义（Semantics）**：字段中的信息含义
- **规则（Rules）**：进程何时发送消息、如何响应消息

## 六、Web 应用工作原理

**Web（万维网）**应用由两个程序组成：
1. **浏览器程序（Browser / Client）**：运行在用户主机上（台式机、笔记本、手机等）
2. **Web 服务器程序（Web Server）**：运行在服务器主机上

**通信过程**：
```
用户浏览器                    Web 服务器
   |  HTTP GET /index.html      |
   |─────────────────────────→  |
   |  HTTP 200 OK + HTML数据    |
   |←─────────────────────────  |
```

**网络层次关系**（以 Alice 访问 Bob 书店为例）：
- **逻辑连接**发生在 Alice 电脑的应用层和 Bob 服务器的应用层之间
- **实际通信**经过多个路由器和物理链路
- 传输层负责**进程到进程**的消息传递

## 七、BitTorrent（P2P 文件分发）

BitTorrent 是最流行的 P2P 文件分发协议（由 Bram Cohen 开发）：

| 概念 | 说明 |
|------|------|
| **文件分发** | 从单一源向大量对等节点分发文件（如 Linux 系统镜像） |
| **客户端-服务器模式的问题** | 服务器需向每个对等节点发送一份副本，带宽压力巨大 |
| **P2P 优势** | 每个对等节点可将已下载的部分转发给其他节点，分担服务器压力 |
| **自扩展性** | 对等节点越多，分发能力越强 |
