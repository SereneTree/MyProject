## 一、传输层回顾

**传输层（Transport Layer）**位于 TCP/IP 的第 4 层，提供**进程到进程（Process-to-Process）**的通信。

- 依赖网络层的**主机到主机**通信服务
- 对网络层如何实现该服务**一无所知**
- 互联网传输层提供两种协议：**TCP** 和 **UDP**

```
TCP/IP 五层模型：
应用层  ← 进程到进程
传输层  ← 进程到进程（TCP / UDP）
网络层  ← 主机到主机
数据链路层 ← 节点到节点
物理层
```

## 二、多路复用与多路分解（Multiplexing & Demultiplexing）

### 2.1 概念

| 术语 | 方向 | 说明 |
|------|------|------|
| **多路复用（Multiplexing）** | 发送方（向下） | 传输层从多个套接字收集数据，加上头部，向下传递给网络层 |
| **多路分解（Demultiplexing）** | 接收方（向上） | 传输层将收到的段正确分发给对应的套接字/进程 |

### 2.2 实现机制

**端口号（Port Number）**：用于标识进程/套接字的 16 位数字（0–65535）

- **UDP 套接字**：由二元组标识（目的 IP 地址，目的端口号）
- **TCP 套接字**：由四元组标识（源 IP、源端口、目的 IP、目的端口）

> TCP 四元组使得来自不同源的多个连接可以同时使用同一目的端口（如 Web 服务器的 80 端口）。

## 三、拥塞控制（Congestion Control）

### 3.1 什么是拥塞？

**拥塞（Congestion）**：网络中发送的数据包数量（负载）超过了网络的处理能力（容量）。

- **拥塞控制**：用于控制拥塞、将负载保持在容量以下的**机制和技术**。

### 3.2 拥塞的影响

- 数据包延迟增大
- 数据包丢失增多
- 网络吞吐量下降

## 四、可靠数据传输基础

### 4.1 ACK 确认机制

```
发送方                            接收方
  │──── 数据包（序列号 N）────→   │
  │←─── ACK（确认 N 已收到）───   │
  │ 若未收到 ACK → 重传该数据包   │
```

- **发送方**将消息分割成数据包，逐包发送
- **接收方**对每个成功接收的数据包发送 **ACK（确认号）**
- 若发送方未在超时时间内收到 ACK → **重传**该数据包（只重传未确认的包）

### 4.2 序列号（Sequence Number）

- 每个数据包分配一个唯一**序列号（Sequence Number）**
- 用于：标识数据包、检测丢失、保证有序接收

## 五、滑动窗口协议（Sliding Window Protocol）

### 5.1 为什么需要滑动窗口？

**停止-等待（Stop-and-Wait）**效率低：发送一个包后必须等待 ACK 才能发下一个。

**滑动窗口（Sliding Window）**：允许发送方在收到 ACK 之前发送多个数据包，提高效率。

### 5.2 窗口大小与序列号

设序列号使用 **m 比特**：

| 参数 | 公式 | 说明 |
|------|------|------|
| 序列号范围 | $0$ 到 $2^m - 1$ | 共 $2^m$ 个序列号 |
| 最大序列号 | $2^m - 1$ | 例如 m=4，最大序列号 = 15（0~15） |

**例题**：缓冲区大小为 16 字节，需要 m=4 比特寻址，最大序列号 = $2^4 - 1 = 15$

### 5.3 Go-Back-N（GBN）协议

| 特征 | 说明 |
|------|------|
| 发送窗口大小 | 最大 $2^m - 1$ |
| 接收窗口大小 | 1（只接受按序到达的包） |
| 出错处理 | 丢弃出错包及其后所有包，从出错包重传 |
| 缺点 | 效率低：一个包出错导致大量重传 |

### 5.4 选择重传（Selective Repeat / SR）协议

| 特征 | 说明 |
|------|------|
| 发送窗口大小 | 最大 $2^{m-1}$ |
| 接收窗口大小 | $2^{m-1}$（可缓存乱序到达的包） |
| 出错处理 | **只重传**出错的特定数据包 |
| 优点 | 效率更高，避免不必要的重传 |

**SR 工作步骤**：
1. 发送方将数据分成固定大小的数据包，分配序列号
2. 发送方和接收方各维护一个"窗口"，指示已发送/已接收的包范围
3. 发送方收到每个数据包的独立 ACK
4. 若某个包的 ACK 超时 → **只重传该包**，不重传整个窗口
5. 接收方只接受窗口内的包；窗口外的包被**丢弃**

**SR 示例**：
- 缓冲区大小 = 8（序列号 0~7）
- 窗口大小 = 4（0,1,2,3）
- m = 3 比特，最大序列号 = $2^3 - 1 = 7$

### 5.5 GBN vs SR 对比

| 对比项 | Go-Back-N (GBN) | 选择重传 (SR) |
|--------|-----------------|--------------|
| 发送窗口 | $\leq 2^m - 1$ | $\leq 2^{m-1}$ |
| 接收窗口 | 1 | $2^{m-1}$ |
| 重传策略 | 出错包及其后所有包 | 只重传出错包 |
| 接收方缓冲 | 不需要（丢弃乱序包） | 需要（缓存乱序包） |
| 效率 | 较低 | 较高 |

## 六、流量控制（Flow Control）

**流量控制**：防止**发送方**数据淹没**接收方**的缓冲区。

- 接收方通过告知发送方自己的**可用缓冲区大小（接收窗口）**来控制发送速率
- TCP 在段头中使用 **接收窗口（Receive Window）** 字段实现流量控制

```
接收方缓冲区：
┌─────────────────────────────────┐
│ 已处理 │ 已收到但未处理 │ 空闲  │
└─────────────────────────────────┘
                        ↑ 接收方告诉发送方：你还能发多少字节
```

## 七、互联网五层通信总结

```
┌───────────────────────────────────────────────────┐
│  应用层：进程 A ←────────────────────→ 进程 B     │
│           ↑HTTP、SMTP、DNS 等协议↑                 │
├───────────────────────────────────────────────────┤
│  传输层：TCP Socket ←──────────────→ TCP Socket   │
│           ↑ 多路复用/分解，流量控制 ↑              │
├───────────────────────────────────────────────────┤
│  网络层：IP 数据报在路由器间转发                   │
├───────────────────────────────────────────────────┤
│  数据链路层：帧在相邻节点间传输                    │
├───────────────────────────────────────────────────┤
│  物理层：比特在物理介质上传输                      │
└───────────────────────────────────────────────────┘
```

## 八、关键公式汇总

| 公式 | 说明 |
|------|------|
| 序列号范围：$0$ 到 $2^m - 1$ | m = 地址所需比特数 |
| GBN 发送窗口最大值：$2^m - 1$ | 保留一个序列号用于区分 |
| SR 发送/接收窗口最大值：$2^{m-1}$ | 避免新旧数据包混淆 |
| 缓冲区大小 $N$ → 需要比特数 $m = \lceil \log_2 N \rceil$ | |
