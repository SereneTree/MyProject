## 一、NAT（网络地址转换）

### 1.1 NAT 的作用

**问题**：IPv4 地址有限，小型组织往往只有一个或少量公网 IP 地址，但内部有多台设备。

**解决方案**：NAT 技术允许：
- 内部网络使用**私有地址**进行内部通信
- 对外使用一个（或少量）**全局公网 IP 地址**与互联网通信

**核心特性**：
- 必须通过一台运行 NAT 软件的 **NAT 路由器**连接全球互联网
- 私有网络对互联网**不可见**；互联网只看到 NAT 路由器的全局地址
- 例：内部多台设备（10.0.0.1、10.0.0.2 等），外部只看到一个公网 IP（如 138.76.29.7）

### 1.2 NAT 地址转换机制

```
【发出数据包】
私有网络 → NAT 路由器（替换源地址：私有IP → 公网IP）→ 互联网

【接收数据包】
互联网 → NAT 路由器（替换目的地址：公网IP → 私有IP）→ 私有网络
```

**问题**：NAT 路由器如何知道返回的数据包应转发给哪台内部主机？
- **答案**：通过 **NAT 转换表（Translation Table）**

## 二、NAT 转换表的三种设计方案

### 方案一：使用单一全局 IP 地址

- 转换表只有**两列**：私有地址 + 外部目的地址
- **限制**：同一时刻只允许**一台**内部主机与同一外部服务器通信

```
私有地址         外部地址（目的地）
10.0.0.1  ←→  25.8.2.10
```

### 方案二：使用 IP 地址池（Pool of IP Addresses）

- NAT 路由器使用**多个**全局 IP 地址（如 200.24.5.8, .9, .10, .11）
- 允许多台内部主机**同时**与同一外部主机通信
- **限制**：每台内部主机不能同时访问同一外部主机的**两个**服务（如 HTTP + Telnet）

### 方案三：使用 IP 地址 + 端口号（最常用）

- 转换表有**五列**：源 IP、源端口、目的 IP、目的端口、传输层协议
- 实现**多对多**关系（多台内部主机可同时访问同一外部主机的多个服务）
- **这是互联网中最常用的 NAT 实现方式**

**完整示例**：

```
NAT 转换表：
WAN 侧地址（公网）          LAN 侧地址（私有）
138.76.29.7:5001      ←→   10.0.0.1:3345

数据包流向：
主机 10.0.0.1:3345 发送数据到 128.119.40.186:80
  ↓ NAT 路由器转换源地址
报文源地址变为 138.76.29.7:5001
  ↓ 发往互联网目的 128.119.40.186:80
返回报文目的：138.76.29.7:5001
  ↓ NAT 路由器查表，转换目的地址
返回报文最终到达 10.0.0.1:3345
```

### 2.1 UPnP（通用即插即用）

- **NAT 穿透（NAT Traversal）**越来越多由 **UPnP** 实现
- UPnP 允许主机**发现并配置**附近的 NAT
- 应用程序可请求 NAT 创建映射：（私有IP, 私有端口）↔（公网IP, 公网端口）
- 外部节点可通过公网端口发起 TCP 连接，实现 P2P 应用穿越 NAT

## 三、IPv6 协议

### 3.1 IPv6 的产生背景

- IPv4 地址空间（32 位，约 43 亿）即将耗尽
- IPv6 将 IP 地址从 **32 位**扩展到 **128 位**，地址空间接近无限

### 3.2 IPv6 vs IPv4 主要改进

| 特性 | IPv4 | IPv6 |
|------|------|------|
| **地址长度** | 32 位 | **128 位** |
| **头部长度** | 可变（最小 20 字节） | **固定 40 字节** |
| **分片处理** | 路由器可分片 | **只有源和目的端可分片**（路由器不分片） |
| **头部校验和** | 有 | **无**（由上层协议处理）|
| **选项字段** | 在头部中 | 移出标准头部（作为"下一个头部"指向）|
| **流标签** | 无 | **有（20 位 Flow Label）** |
| **处理速度** | 较慢（可变头部） | **更快**（固定头部）|

### 3.3 IPv6 数据报格式（头部字段）

**固定 40 字节头部**：

```
┌────────┬─────────────┬──────────────────────────────┐
│版本(4b)│流量类别(8b)  │        流标签(20b)            │
├────────┴─────────────┴──────────────────────────────┤
│    载荷长度(16b)      │ 下一个头部(8b)│ 跳数限制(8b) │
├────────────────────────────────────────────────────────┤
│                   源地址（128 位）                     │
├────────────────────────────────────────────────────────┤
│                   目的地址（128 位）                   │
├────────────────────────────────────────────────────────┤
│                   数据（载荷）                         │
└────────────────────────────────────────────────────────┘
```

**各字段说明**：

| 字段 | 大小 | 说明 |
|------|------|------|
| **版本（Version）** | 4 位 | IP 版本号（IPv6 = 6） |
| **流量类别（Traffic Class）** | 8 位 | 类似 IPv4 的 TOS 字段，区分数据报类型 |
| **流标签（Flow Label）** | 20 位 | 标识一组数据报的流，用于特殊处理（如实时服务） |
| **载荷长度（Payload Length）** | 16 位 | 40 字节固定头部之后的字节数（无符号整数） |
| **下一个头部（Next Header）** | 8 位 | 标识数据字段交给的上层协议（如 TCP=6, UDP=17）；也指向扩展头部 |
| **跳数限制（Hop Limit）** | 8 位 | 类似 IPv4 的 TTL；每经过一台路由器减 1；降至 0 则丢弃 |
| **源地址 / 目的地址** | 各 128 位 | 发送方和接收方的 IPv6 地址 |
| **数据（Data / Payload）** | 可变 | 载荷数据，到达目的地后按 Next Header 字段传给对应协议 |

### 3.4 IPv6 中被移除的字段

| 移除字段 | 原因 |
|----------|------|
| **分片/重组（Fragmentation/Reassembly）** | 路由器不再分片；只在源端和目的端处理；显著提高路由器转发速度。若数据报过大，路由器丢弃并返回 "Packet Too Big" ICMP 错误 |
| **头部校验和（Header Checksum）** | 传输层（TCP/UDP）和链路层（Ethernet）已提供校验，网络层重复校验效率低 |
| **选项字段（Options）** | 移出标准头部，成为"下一个头部"扩展；固定头部长度，加快处理 |

## 四、路由算法（Routing Algorithms）

### 4.1 路由的基本概念

- **路由（Routing）**：确定数据包从发送方到接收方经过的路径
- 路由算法在网络路由器中运行，交换并计算配置转发表所需的信息
- **好路径 = 最小代价（Least Cost）路径**（代价可表示链路物理长度、速度、数据传输率等）

### 4.2 网络图模型

| 图元素 | 对应网络元素 |
|--------|-------------|
| **节点（Node）** | 路由器 |
| **边（Edge）** | 路由器之间的物理链路 |
| **边权重（Weight）** | 链路代价（物理长度、链路速度等） |

路由问题 → 在加权图中找**最低代价路径**。

### 4.3 Dijkstra 算法（最短路径算法）

- 找到从一个源节点到图中**所有其他节点**的最短路径
- 工作原理：
  1. 初始化：源节点距离=0，其他节点距离=∞
  2. **迭代**：选择未访问节点中距离最小的，将其标记为已访问
  3. 更新该节点所有邻居的距离
  4. 重复直到所有节点都被访问

### 4.4 路由类型

| 路由类型 | 交付方式 | 说明 |
|----------|----------|------|
| **单播（Unicast）** | 一对一 | 数据报只发给一个特定目标 |
| **多播（Multicast）** | 一对多 | 数据报发给一组目标 |
| **广播（Broadcast）** | 一对所有 | 数据报发给互联网上所有主机 |

### 4.5 多播路由的应用场景

| 应用 | 说明 |
|------|------|
| **分布式数据库访问** | 用户请求多播到所有数据库位置，有数据的位置响应 |
| **信息传播** | 企业向客户群发送软件更新、新闻等 |
| **视频会议（Teleconferencing）** | 所有参会者接收同样内容 |
| **远程教育（Distance Learning）** | 教授讲课内容多播给特定学生群体 |

## 五、IPv4 vs IPv6 综合对比

| 对比项 | IPv4 | IPv6 |
|--------|------|------|
| **地址长度** | 32 位 | 128 位 |
| **地址表示** | 点分十进制（`192.168.1.1`） | 冒号十六进制（`2001:db8::1`） |
| **地址空间** | $2^{32} \approx 43$ 亿 | $2^{128}$ ≈ 3.4×10³⁸ |
| **头部** | 可变长，最小20字节 | 固定40字节 |
| **分片** | 路由器可分片 | 只有端系统可分片 |
| **头部校验和** | 有 | 无 |
| **选项** | 在标准头部中 | 通过扩展头部实现 |
| **流标签** | 无 | 有（20位） |
| **部署情况** | 广泛使用 | 自2006年起在公共互联网上日益增长 |
