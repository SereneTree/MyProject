## 一、为什么需要网络分层？

**问题**：互联网网络极其复杂，包含众多"组件"：主机、路由器、各种传输介质、应用程序、协议、硬件与软件。

**解决方案**：通过**分层（Layering）**来组织网络结构，每一层负责特定的功能，层与层之间通过接口通信。

**分层的好处**：
- 降低设计复杂度
- 每层相对独立，易于修改和维护
- 标准化接口，促进互操作性

---

## 二、TCP/IP 五层模型

TCP/IP 协议栈是互联网使用的实际标准，共分为**五层**：

```
┌─────────────────────────┐
│    应用层 (Application)  │  ← 数据 (Data)
├─────────────────────────┤
│    传输层 (Transport)    │  ← 段 (Segment)
├─────────────────────────┤
│    网络层 (Network)      │  ← 数据报 (Datagram)
├─────────────────────────┤
│  数据链路层 (Data Link)  │  ← 帧 (Frame)
├─────────────────────────┤
│    物理层 (Physical)     │  ← 比特 (Bits)
└─────────────────────────┘
```

### 各层功能详解

| 层次 | 名称 | 主要功能 | 典型协议 | 数据单元 |
|------|------|----------|----------|----------|
| 第 5 层 | **应用层（Application Layer）** | 为用户应用程序提供网络服务 | HTTP、FTP、SMTP、DNS | 数据（Data） |
| 第 4 层 | **传输层（Transport Layer）** | 进程到进程（Process-to-Process）通信，提供可靠或不可靠传输 | TCP、UDP | 段（Segment） |
| 第 3 层 | **网络层（Network Layer）** | 主机到主机（Host-to-Host）通信，路由选择 | IP | 数据报（Datagram） |
| 第 2 层 | **数据链路层（Data Link Layer）** | 节点到节点（Node-to-Node）通信，帧的传输 | Ethernet、Wi-Fi | 帧（Frame） |
| 第 1 层 | **物理层（Physical Layer）** | 比特流的物理传输，定义物理接口 | — | 比特（Bits） |

## 三、OSI 七层模型

OSI（Open Systems Interconnection）模型由 ISO 制定，共 7 层，是理论参考模型：

```
┌──────────────────────────┐
│  7. 应用层 (Application)  │
├──────────────────────────┤
│  6. 表示层 (Presentation) │  ← TCP/IP 中并入应用层
├──────────────────────────┤
│  5. 会话层 (Session)      │  ← TCP/IP 中并入应用层
├──────────────────────────┤
│  4. 传输层 (Transport)    │
├──────────────────────────┤
│  3. 网络层 (Network)      │
├──────────────────────────┤
│  2. 数据链路层 (Data Link) │
├──────────────────────────┤
│  1. 物理层 (Physical)     │
└──────────────────────────┘
```

| OSI 层 | TCP/IP 层 | 对应关系 |
|--------|-----------|----------|
| 应用层（7） | 应用层 | 合并了 OSI 的 5、6、7 层 |
| 表示层（6） | 应用层 | 同上 |
| 会话层（5） | 应用层 | 同上 |
| 传输层（4） | 传输层 | 一一对应 |
| 网络层（3） | 网络层 | 一一对应 |
| 数据链路层（2） | 数据链路层 | 一一对应 |
| 物理层（1） | 物理层 | 一一对应 |

---

## 四、三种通信类型

| 通信类型 | 所在层次 | 说明 |
|----------|----------|------|
| **主机到主机（Host-to-Host）** | 网络层 | 从源计算机到目标计算机的完整路径 |
| **进程到进程（Process-to-Process）** | 应用层 & 传输层 | 从源进程到目标进程的消息传递 |
| **节点到节点（Node-to-Node）** | 数据链路层 | 从当前设备（主机/路由器/交换机）到下一个设备 |

## 五、封装与解封装（Encapsulation & Decapsulation）

### 封装过程（发送方，自上而下）

```
应用数据
   ↓  + 应用层头部
应用层 PDU (Data)
   ↓  + 传输层头部
传输层 PDU (Segment / 段)
   ↓  + 网络层头部
网络层 PDU (Datagram / 数据报)
   ↓  + 链路层头部 & 尾部
数据链路层 PDU (Frame / 帧)
   ↓  转换为比特流
物理层 (Bits / 比特)
```

### 解封装过程（接收方，自下而上）

与封装过程相反：每层接收数据后，去掉本层头部，将"载荷（Payload）"传给上一层。

> **关键原则**：路由器只处理到网络层（不对传输层和应用层的数据解封装），仅检查 IP 头部进行转发。

## 六、协议（Protocol）的概念

**协议**是网络中通信实体之间共同遵守的**规则和约定**，规定了：
- 数据格式（Format）
- 消息顺序（Order）
- 发送/接收消息时采取的动作（Actions）

每一层都有自己的协议：
- 应用层：HTTP、FTP、SMTP、DNS
- 传输层：TCP、UDP
- 网络层：IP
- 数据链路层：Ethernet、802.11（Wi-Fi）

---

## 七、互联网通信的完整流程示意

以 Alice 向 Bob 的在线书店下订单为例：

1. **应用层**（Alice 的电脑）：浏览器发出 HTTP 请求
2. **传输层**：TCP 将数据分段，添加端口号
3. **网络层**：IP 添加源/目的 IP 地址，数据路由经过 R2→R4→R5→R7
4. **数据链路层**：帧封装，节点到节点传输
5. **物理层**：比特流通过物理介质传输
6. 到达 Bob 的服务器后，各层**逆序解封装**

> **逻辑连接**发生在应用层（Alice 的浏览器 ↔ Bob 服务器的应用层），**实际通信**通过所有中间设备和物理信道完成。

---

## 八、核心概念总结

```
发送方                           接收方
Application → [HTTP 等]  → Application
Transport   → [TCP/UDP]  → Transport
Network     → [IP]       → Network
Data Link   → [Ethernet] → Data Link
Physical    → [比特流]   → Physical
              ↑
         路由器（只到网络层）
```
