## 一、数据链路层概述

### 1.1 位置与职责

```
TCP/IP 五层：
应用层
传输层
网络层    ← 主机到主机
数据链路层 ← 节点到节点（本讲内容）
物理层
```

- **节点（Node）**：源主机、目标主机、路由器、交换机、Wi-Fi 接入点
- **链路（Link）**：节点之间的网络（连接）
- 数据链路层的基本服务：**在单条通信链路上，将数据报从一个节点移动到相邻节点**

### 1.2 数据链路层的位置特殊性

| 设备 | 数据链路层数量 |
|------|---------------|
| 源/目标主机 | 各 1 个 |
| 中间路由器 | **2 个**（从一个网络接收，向另一个网络发送） |

### 1.3 链路类型

| 类型 | 说明 | 协议 |
|------|------|------|
| **点对点链路（Point-to-Point）** | 两设备专用连接（1对1） | PPP、HDLC |
| **广播链路（Broadcast）** | 多设备共享链路（多对多） | Ethernet、Wi-Fi（802.11） |

## 二、数据链路层四大服务

### 2.1 成帧（Framing）

- 链路层协议将每个网络层数据报**封装**在链路层**帧（Frame）**中，再通过链路传输
- 帧结构：**数据字段**（存放网络层数据报）+ **头部和尾部字段**
- 使用特殊的 8 位标志字节（**01111110**）作为帧的开始和结束标识符

```
┌─────────┬─────────────────────────────┬────────┐
│  头部   │    数据（网络层数据报）      │  尾部  │
│ (Header)│         (Payload)            │(Trailer│
└─────────┴─────────────────────────────┴────────┘
```

### 2.2 介质访问控制（Medium Access / MAC）

- **MAC 协议**：规定帧如何在链路上传输的规则
- 点对点链路：简单，链路空闲时即可发送
- 广播链路（多节点共享）：MAC 协议**协调**多个节点的帧传输，防止冲突

### 2.3 可靠交付（Reliable Delivery）

- 保证每个网络层数据报无误地跨越链路传输
- 通过**确认（ACK）和重传**机制实现
- **使用场景**：高错误率链路（如无线链路），本地纠错效率高
- **不使用场景**：低错误率链路（光纤、同轴电缆、许多铜线）——可靠交付是不必要的开销，很多有线链路协议**不提供**此服务

### 2.4 错误检测（Error Detection）

- 接收节点的链路层硬件可能将 1 误判为 0，或将 0 误判为 1（由信号衰减和电磁噪声引起）
- 发送节点在帧中加入**错误检测位**
- 接收节点执行错误检查，若发现错误则**丢弃帧**
- 链路层的错误检测通常比互联网校验和（checksum）更复杂，在**硬件**中实现

**错误纠正（Error Correction）**：接收方不仅检测错误，还能确定错误**位置**并纠正。

## 三、数据链路层的实现

- 实现于**网络适配器（Network Adapter）**，即**网卡（NIC，Network Interface Card）**
- NIC 核心是**数据链路层控制器（Controller）**（通常是单芯片）
- 大多数功能**在硬件中实现**；部分高级功能在主机 CPU 上的软件中实现

**发送方 NIC**：
1. 从主机内存取出数据报
2. 封装进链路层帧（填写各字段）
3. 按链路访问协议将帧发送到链路

**接收方 NIC**：
1. 接收完整的帧
2. 解封装，提取网络层数据报
3. 检测链路层错误；将数据报传给网络层

## 四、MAC 地址（物理地址）

### 4.1 什么是 MAC 地址？

- **MAC = Media Access Control 地址**，也称为 **LAN 地址**或**物理地址**
- 每个网络适配器（NIC）有唯一的 MAC 地址
- 大多数 LAN（Ethernet、802.11 Wi-Fi）使用 **6 字节（48 位）**的 MAC 地址
- 以**十六进制**表示，如 `1A-2B-3C-4D-5E-6F`
- MAC 地址在制造时**永久烧入** NIC（不可更改）
- 无论计算机连接到哪个网络，MAC 地址始终不变

### 4.2 MAC 地址结构

```
前 3 字节（24 位）：OUI（组织唯一标识符）
  → 标识网卡制造商
后 3 字节（24 位）：NIC Specific
  → 标识该制造商的具体网卡

示例制造商 OUI：
  00000C → Cisco
  080007 → Apple
  080009 → Hewlett-Packard
  0020AF → 3Com
```

### 4.3 MAC 地址管理

- **IEEE**（电气和电子工程师协会）管理 MAC 地址空间
- 制造商向 IEEE 购买一块 MAC 地址空间
- **广播地址**：`FF-FF-FF-FF-FF-FF`（48 个连续的 1）

### 4.4 查看 MAC 地址的命令

| 操作系统 | 命令 |
|----------|------|
| Windows | `getmac` / `getmac /v`（详细）/ `ipconfig /all` |
| macOS | `ifconfig en0` |
| Linux | `ifconfig` |

## 五、ARP 协议（地址解析协议）

### 5.1 为什么需要 ARP？

- 网络中同时存在 **IP 地址（网络层）**和 **MAC 地址（链路层）**
- 链路层需要 MAC 地址来传输帧，但上层只知道目的 IP 地址
- **ARP（Address Resolution Protocol）**负责将 **IP 地址解析（映射）为 MAC 地址**

### 5.2 ARP vs DNS

| 协议 | 解析对象 | 作用范围 |
|------|----------|----------|
| **DNS** | 主机名 → IP 地址 | 全球互联网（任意主机） |
| **ARP** | IP 地址 → MAC 地址 | **仅限同一子网**内的主机和路由器接口 |

> 如果加利福尼亚州的节点试图用 ARP 解析密西西比州节点的 IP 地址，ARP 会报错。

### 5.3 ARP 表（ARP Table / ARP Cache）

- 每台主机和路由器在内存中维护一张 **ARP 表**
- 表中包含：**IP 地址 → MAC 地址**的映射 + **TTL（生存时间）**
- TTL 到期后，该条目从表中删除
- ARP 表不一定包含子网中所有主机的条目

### 5.4 ARP 工作流程

**情况 1：ARP 表中已有目的 MAC 地址**
→ 直接使用，无需发送 ARP 请求

**情况 2：ARP 表中无目的 MAC 地址**

```
发送方（222.222.222.220）想发数据给（222.222.222.222）

1. 发送方构造 ARP 查询包（包含发送方/接收方的 IP 和 MAC）
2. 将 ARP 查询包发送到广播 MAC 地址：FF-FF-FF-FF-FF-FF
3. 子网上所有适配器接收帧 → 各自的 ARP 模块检查 IP 地址
4. IP 匹配的主机（222.222.222.222）发送 ARP 响应包，包含其 MAC 地址
5. 发送方（222.222.222.220）更新 ARP 表，完成 IP 数据报的链路层封装
```

### 5.5 跨子网发送数据报

发送数据报到另一个子网时，需要经过路由器：

```
主机 A（子网1）想发数据给主机 B（子网2）
  ↓ 1. 用 ARP 获取路由器接口（子网1侧）的 MAC 地址
  ↓ 2. 将 IP 数据报封装进帧，目的 MAC = 路由器接口 MAC
  ↓ 3. 路由器接收帧，解封装，查路由表，确定出口接口
  ↓ 4. 路由器用 ARP 获取主机 B 的 MAC 地址（子网2侧）
  ↓ 5. 将数据报封装进新帧，目的 MAC = 主机 B 的 MAC
  ↓ 6. 发送到子网 2，主机 B 接收
```

## 六、以太网（Ethernet）

### 6.1 以太网概述

- 以太网是最常见的有线 LAN 技术（IEEE 802.3 标准）
- 工作在 TCP/IP 模型的两层：**物理层**和**数据链路层**
- 以太网的协议数据单元（PDU）是**帧（Frame）**
- 早期以太网使用**总线拓扑**（广播 LAN）；现代以太网使用**基于交换机的星型拓扑**

### 6.2 以太网帧结构

```
┌──────────┬──────────┬─────────┬────────────────────┬───────┐
│目的 MAC  │源 MAC   │类型字段 │  数据（IP 数据报） │  CRC  │
│ (6字节)  │ (6字节)  │ (2字节) │  (46~1500 字节)    │(4字节)│
└──────────┴──────────┴─────────┴────────────────────┴───────┘
```

| 字段 | 大小 | 作用 |
|------|------|------|
| **目的 MAC 地址** | 6 字节 | 接收适配器的 MAC 地址 |
| **源 MAC 地址** | 6 字节 | 发送适配器的 MAC 地址 |
| **类型字段** | 2 字节 | 标识上层协议（如 IPv4 = 0x0800，IPv6 = 0x86DD）；实现以太网的多路复用 |
| **数据字段** | 46~1500 字节 | 承载 IP 数据报 |
| **CRC（循环冗余校验）** | 4 字节 | 错误检测；接收方用 CRC 检测帧中的位错误 |

### 6.3 以太网的服务特性

| 特性 | 说明 |
|------|------|
| **无连接（Connectionless）** | 发送适配器无需与接收适配器握手 |
| **不可靠（Unreliable）** | CRC 失败时直接丢弃帧，不发送 ACK 或 NAK |

> **以太网不可靠但简单便宜**：链路层不提供可靠传输，由上层（如 TCP）负责可靠性。

## 七、链路层交换机（Link-Layer Switch）

### 7.1 交换机的作用

- 接收传入的链路层帧，将其转发到相应的输出链路
- 主机/路由器将帧寻址到另一台主机/路由器（**不是**交换机本身）
- 交换机对主机透明（主机不知道交换机的存在）

### 7.2 交换机的两个功能

| 功能 | 说明 |
|------|------|
| **过滤（Filtering）** | 决定帧应被转发还是被丢弃 |
| **转发（Forwarding）** | 决定帧应被发送到哪个接口，并将其移动到该接口 |

### 7.3 交换机表（Switch Table）

交换机维护一张**交换机表**，每条目包含：
1. **MAC 地址**
2. 通向该 MAC 地址的**交换机接口**
3. 该条目放入表中的**时间**

### 7.4 交换机的过滤与转发逻辑

假设目的 MAC 地址为 DD-DD-DD-DD-DD-DD，从接口 x 到达：

| 情况 | 处理方式 |
|------|----------|
| **表中无该地址** | **广播**：将帧复制到除接口 x 外的所有接口 |
| **表中有该地址，对应接口 y ≠ x** | **转发**：将帧发送到接口 y |
| **表中有该地址，对应接口 = x** | **过滤（丢弃）**：源和目标在同一网段，无需转发 |

## 八、核心概念总结

```
数据报到达目的地的完整链路层过程：

源主机
  ↓ 1. ARP 获取目的 MAC（或默认网关 MAC）
  ↓ 2. 封装 IP 数据报进 Ethernet 帧（目的 MAC + 源 MAC + 类型 + 数据 + CRC）
  ↓ 3. 通过 NIC 发送帧

中间交换机
  ↓ 查交换机表（MAC → 接口）→ 转发/广播/丢弃

路由器（跨子网时）
  ↓ 解封装帧，提取 IP 数据报
  ↓ 查路由表，确定出口接口
  ↓ ARP 获取下一跳 MAC
  ↓ 重新封装进新帧发送

目的主机
  ↓ NIC 检查目的 MAC = 自身 MAC → 提取 IP 数据报 → 交给网络层
```
