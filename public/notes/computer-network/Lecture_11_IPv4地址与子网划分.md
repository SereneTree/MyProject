## 一、网络层功能与协议概述

### 1.1 网络层三大功能

| 功能 | 说明 |
|------|------|
| **数据包处理** | 寻址（Addressing）、数据报格式化 |
| **路由处理** | 计算转发表，确定数据报从源到目标的路径 |
| **错误处理** | 提供数据报错误报告机制 |

### 1.2 网络层主要协议

| 协议 | 功能 |
|------|------|
| **IPv4** | 封包化、寻址、转发、交付 |
| **IGMP** | 辅助 IPv4 进行路由（组播路由） |
| **ARP** | 将网络层地址（IP）映射到链路层地址（MAC） |
| **ICMP** | 辅助 IPv4 处理网络层交付中可能发生的错误 |

## 二、IPv4 数据报头部字段

IPv4 数据报 = 头部（Header）+ 数据（Data）

**最小头部大小：20 字节**（无选项字段时）

| 字段 | 大小 | 说明 |
|------|------|------|
| **版本号（Version）** | 4 位 | 指定 IP 协议版本（IPv4 = 4） |
| **头部长度（Header Length）** | 4 位 | IP 数据报头部长度（通常 = 20 字节） |
| **服务类型（TOS）** | 8 位 | 区分不同类型的数据报（如实时 vs 非实时） |
| **数据报总长度（Datagram Length）** | 16 位 | 头部 + 数据的总字节数；理论最大 65,535 字节，实际通常 ≤ 1,500 字节 |
| **标识符、标志、分片偏移** | 各位 | 与 IP **分片**相关 |
| **生存时间（TTL）** | 8 位 | 防止数据报无限循环；每经过一台路由器减 1；TTL = 0 时丢弃 |
| **协议（Protocol）** | 8 位 | 标识上层协议：6 = TCP，17 = UDP |
| **头部校验和（Checksum）** | 16 位 | 检测头部中的位错误 |
| **源 IP 地址** | 32 位 | 发送方 IP 地址 |
| **目的 IP 地址** | 32 位 | 接收方 IP 地址（通常通过 DNS 查询获得） |
| **选项（Options）** | 可变 | 扩展 IP 头部（通常为空） |
| **数据（Data/Payload）** | 可变 | 传输层段（TCP 或 UDP 的数据） |

> **开销计算**：一个携带 TCP 段的 IPv4 数据报有 40 字节头部（20 字节 IP + 20 字节 TCP），再加应用层数据。

## 三、IPv4 地址

### 3.1 IP 地址基本概念

- **IPv4 地址**：32 位地址，唯一且通用地标识主机或路由器与互联网的连接
- **关键**：IP 地址是**接口（Interface）**的地址，而不是主机或路由器本身的地址
  - 路由器有多个接口 → 有多个 IP 地址
  - 若设备移到另一个网络，IP 地址可能改变
- 若设备通过两个网络接入互联网，则有**两个 IPv4 地址**

### 3.2 地址空间

$$\text{地址空间} = 2^{32} = 4{,}294{,}967{,}296 \approx 43 \text{ 亿}$$

---

## 四、IPv4 地址结构：前缀与后缀

32 位 IPv4 地址分为两部分：

```
┌─────────────────────┬───────────────────────┐
│    前缀（Prefix）   │    后缀（Suffix）      │
│    n 位，定义网络   │   32-n 位，定义节点   │
└─────────────────────┴───────────────────────┘
```

---

## 五、CIDR 表示法（无类域间路由）

**CIDR（Classless Interdomain Routing）**，也称为**斜线表示法（Slash Notation）**：

$$\text{地址/前缀长度} \quad \text{如：} 167.199.170.82/27$$

### 5.1 从地址提取信息

$$N = 2^{32-n}$$  （网络中的地址数量，n 为前缀长度）

- **首地址（First Address）**：保留前 n 位，将后 (32-n) 位全设为 **0**
- **末地址（Last Address）**：保留前 n 位，将后 (32-n) 位全设为 **1**

### 5.2 计算例题

**例题**：地址 `167.199.170.82/27`，前缀长度 n = 27

| 参数 | 计算 | 结果 |
|------|------|------|
| 地址数量 | $2^{32-27} = 2^5$ | **32 个地址** |
| 首地址 | 保留前27位，后5位设0 | `167.199.170.64/27` |
| 末地址 | 保留前27位，后5位设1 | `167.199.170.95/27` |

**二进制计算过程**：
```
82 的二进制：01010010
前27位保留，后5位清零：01000000 = 64  → 首地址：167.199.170.64
后5位全1：01011111 = 95             → 末地址：167.199.170.95
```

## 六、子网（Subnet）

### 6.1 什么是子网？

- **子网（Subnet / Subnetwork）**：将一个大的 IP 地址块划分为多个较小的地址范围
- **子网地址（Subnetwork Address）**：网络的标识符；每个网络由其网络地址标识
- 路由器用子网地址来决定将数据报从哪个接口发出

### 6.2 子网表示法示例

```
223.1.1.0/24：
  前缀长度 n = 24
  主机位 = 32 - 24 = 8 位
  可用地址：223.1.1.1 至 223.1.1.254（共 256 个地址）
  
该子网包含：
  3 台主机接口：223.1.1.1, 223.1.1.2, 223.1.1.3
  1 台路由器接口：223.1.1.4
```

### 6.3 子网设计（Subnet Design）

**设计规则**：
1. 每个子网的地址数量必须是 **2 的幂**
2. 每个子网的前缀长度：$n_{sub} = 32 - \log_2 N_{sub}$
3. 较大子网优先分配地址（从大到小分配，保证起始地址可被地址数整除）

**设计例题**：已分配地址块 `14.24.74.0/24`（N = 256 个地址），需划分三个子网（120、60、10 台主机）：

| 子网 | 实际需求 | 分配数量（2的幂） | 前缀长度 | 首地址 | 末地址 |
|------|----------|-----------------|---------|--------|--------|
| 子网1 | 120 | 128 ($2^7$) | n = 32-7 = **25** | `14.24.74.0/25` | `14.24.74.127/25` |
| 子网2 | 60 | 64 ($2^6$) | n = 32-6 = **26** | `14.24.74.128/26` | `14.24.74.191/26` |
| 子网3 | 10 | 16 ($2^4$) | n = 32-4 = **28** | `14.24.74.192/28` | `14.24.74.207/28` |
| 预留 | — | 48 | — | `14.24.74.208` | `14.24.74.255` |

## 七、地址分配

### 7.1 地址分配层级

```
ICANN（互联网名称与数字地址分配机构）
  ↓ 分配大块地址
ISP（互联网服务提供商）
  ↓ 分配子块（1、2、4、8、16... 个地址）
组织/家庭/企业
  ↓ 分配给具体主机
主机（手动 or DHCP）
```

### 7.2 DHCP（动态主机配置协议）

- **DHCP（Dynamic Host Configuration Protocol）**：自动为主机分配 IP 地址的应用层协议
- 使用**客户端-服务器**模式
- 功能：
  - 为主机自动分配 IP 地址（临时或固定）
  - 也可分配子网掩码、默认网关、DNS 服务器地址
- **实际意义**：主机无需手动配置 IP，即插即用

### 7.3 地址聚合（Address Aggregation）

- CIDR 的优势之一：将多个小地址块**合并**为一个更大的地址块用于路由
- ISP 拥有一个大地址块 → 分配给多个客户 → 对外界只宣告 ISP 的大地址块
- 这减少了互联网上路由表的条目数量

## 八、为什么需要 NAT？

**问题**：
- 小企业或家庭被 ISP 分配的地址数量有限
- 同一时刻，并非所有计算机都需要访问互联网
- 部分地址已分配给相邻网络，ISP 无法扩展

**解决方案**：**NAT（Network Address Translation，网络地址转换）**
- 内部网络使用**私有地址**通信
- 对外互联网通信使用一个（或少量）**公网 IP 地址**
- NAT 路由器负责内外地址的转换
